Cuando `rustc` rechaza tu programa no te está regañando: te está enseñando una regla que tu código incumple, casi siempre con la línea exacta y una propuesta de arreglo. Al compilador se le gana entendiéndolo, no peleando. En esta sección tienes los errores que más aparecen al aprender Rust, cada uno con **el mensaje real** (copiado de compilar el ejemplo con rustc 1.99.1, edición 2024), qué significa, por qué existe la regla y cómo arreglarlo.

¿Tienes un error delante ahora mismo? Pégalo en el [traductor de errores](/errores/traductor/) y te lo explica en español.

## Cómo se lee un error de rustc

Este es el error más frecuente de todos, [E0382](/errores/e0382/):

<NoCompila ej="errores/E0382" />

**Error real** (rustc 1.99.1, edición 2024):

```text
error[E0382]: borrow of moved value: `saludo`
 --> E0382.rs:4:16
  |
2 |     let saludo = String::from("hola");
  |         ------ move occurs because `saludo` has type `String`, which does not implement the `Copy` trait
3 |     let otro = saludo; // la propiedad se mueve a `otro`
  |                ------ value moved here
4 |     println!("{saludo}");
  |                ^^^^^^ value borrowed here after move
  |
help: consider cloning the value if the performance cost is acceptable
  |
3 |     let otro = saludo.clone(); // la propiedad se mueve a `otro`
  |                      ++++++++
```

1. **`error[E0382]`**: el **código** del error. Cada código tiene su ficha aquí y su explicación oficial con `rustc --explain E0382`.
2. **El mensaje** (`borrow of moved value`): qué regla se ha roto, en una frase.
3. **`-->`**: archivo, línea y columna donde está el problema.
4. **Las líneas numeradas** con marcas: `-` y `^` subrayan las piezas de la historia (dónde se creó el valor, dónde se movió, dónde se usó después). Lee las etiquetas en orden.
5. **`note:`** añade contexto y **`help:`** propone un cambio concreto, a veces con las líneas ya corregidas (`+` añade, `-` quita).

Un consejo: arregla siempre **el primer error** y vuelve a compilar. Muchas veces los siguientes son consecuencia del primero.

Algunos errores del comprobador de préstamos **no tienen código**, como [«lifetime may not live long enough»](/errores/vida-insuficiente/). Se leen igual.

## Los diez que más vas a ver

| Código | En una frase |
|---|---|
| [E0382](/errores/e0382/) | Usas una variable después de que su valor se movió a otra variable o a una función. |
| [E0502](/errores/e0502/) | Intentas modificar (o pedir &mut de) un valor mientras sigue vivo un préstamo compartido (&) de él. |
| [E0499](/errores/e0499/) | Pides dos préstamos exclusivos (&mut) del mismo valor y los dos siguen vivos al mismo tiempo. |
| [E0308](/errores/e0308/) | El tipo de un valor no es el que se esperaba en ese sitio (argumento, retorno, rama de if…). |
| [E0277](/errores/e0277/) | Usas un valor en un sitio que exige un trait (Display, Debug, Copy, Add, Iterator…) que su tipo no implementa. |
| [E0599](/errores/e0599/) | Llamas a un método que el tipo no tiene (o que existe pero en un trait que no está importado o no se cumple). |
| [E0106](/errores/e0106/) | Una función o struct usa una referencia sin decir de quién viene o cuánto vive. |
| [E0597](/errores/e0597/) | Una referencia se sigue usando después de que el valor al que apunta haya salido de su ámbito. |
| [E0507](/errores/e0507/) | Intentas sacar (mover) un valor que solo tienes prestado, por ejemplo un campo a través de &. |
| [E0425](/errores/e0425/) | Usas una variable, función o tipo que no existe en ese ámbito (a menudo, una errata). |
