> **Mensaje de rustc:** `` cannot move out of type `Registro`, which implements the `Drop` trait ``

## Qué significa

Si un tipo implementa `Drop`, su método `drop` necesitará **todos** sus campos cuando se destruya. Por eso no puedes desmontarlo moviendo sus campos fuera: `drop` recibiría un valor a medias.

## Qué error evita

`drop` podría usar un campo que ya se movió a otro sitio (y que quizá ya se liberó): **uso tras liberar**.

## Ejemplo que lo provoca

<NoCompila ej="errores/E0509" />

**Error real** (rustc 1.99.1, edición 2024):

```text
error[E0509]: cannot move out of type `Registro`, which implements the `Drop` trait
  --> E0509.rs:13:30
   |
13 |     let Registro { texto } = r;
   |                    -----     ^ cannot move out of here
   |                    |
   |                    data moved here because `texto` has type `String`, which does not implement the `Copy` trait
   |
help: consider borrowing the pattern binding
   |
13 |     let Registro { ref texto } = r;
   |                    +++
```

Cómo leerlo: la primera línea dice **qué** pasa; `-->` dice **dónde** (archivo, línea y columna); las marcas `^` y `-` señalan las piezas implicadas, y `help:` propone un arreglo. Léelo siempre de arriba abajo.

## Causas típicas

- Desestructurar con `let Tipo { campo } = valor;` un tipo con `Drop`.
- Mover un campo con `valor.campo` en un tipo con `Drop`.

## Cómo arreglarlo

Toma prestado el campo (`&r.texto`), clónalo, o reemplázalo con `std::mem::take(&mut r.texto)` / `mem::replace`: así el struct sigue completo y `drop` funciona.

Así queda el ejemplo arreglado (botón «Ver arreglo» arriba):

```rust
struct Registro {
    texto: String,
}

impl Drop for Registro {
    fn drop(&mut self) {
        println!("cerrando registro");
    }
}

fn main() {
    let mut r = Registro { texto: String::from("datos") };
    let texto = std::mem::take(&mut r.texto); // deja un String vacío en su sitio
    println!("{texto}");
}
```

**Salida:**

```text
datos
cerrando registro
```
