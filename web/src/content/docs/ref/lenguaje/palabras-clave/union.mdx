Una `union` es como un `struct` en el que **todos los campos ocupan la misma memoria**: en cada momento solo uno tiene sentido, y el compilador no sabe cuál.

## Sinopsis

```text
#[repr(C)]
union Nombre { campo1: T1, campo2: T2 }
Nombre { campo1: valor }        // se inicializa exactamente un campo
unsafe { u.campo2 }             // leer un campo exige unsafe
```

## Qué hace

- El tamaño es el del campo más grande (redondeado a la alineación).
- **Escribir** un campo es seguro. **Leerlo** exige `unsafe`, porque los bytes pueden venir de otro campo: si no forman un valor válido del tipo leído (por ejemplo, un `bool` que no es 0 ni 1), es comportamiento indefinido.
- Los campos deben ser `Copy`, referencias, `ManuallyDrop<T>` o tuplas/arrays de ellos: una union **nunca** ejecuta destructores de sus campos.
- Se usa sobre todo para hablar con código externo que usa uniones y para reinterpretar bits (aunque para eso suelen bastar `f32::to_bits` y similares).
- Hacer `match` sobre una union también es `unsafe`.

`union` es palabra clave débil: solo es especial al **declarar** una unión. `let union = 1;` es válido.

## Errores

<NoCompila ej="ref-lenguaje/kw-union-error" />

`error[E0133]: access to union field is unsafe and requires unsafe block`, con la nota de que el campo podría no estar inicializado.
