`where` introduce una lista de **requisitos** (límites, *bounds*) que deben cumplir los tipos y tiempos de vida genéricos.

## Sinopsis

```text
fn f<T, U>(…) where T: Trait1 + Trait2, U: 'a, Vec<T>: Debug { … }
struct S<T> where T: Clone { … }
impl<T> Trait for S<T> where T: Debug { … }
trait T { fn m(&self) where Self: Sized; }
type Gat<'a> where Self: 'a;
```

## Qué hace

- Hace lo mismo que escribir los límites junto al parámetro (`<T: Debug>`), pero **más legible** cuando hay muchos.
- Permite límites que no caben en la lista de parámetros: sobre tipos compuestos (`Vec<T>: Debug`), sobre tipos asociados (`T::Item: Clone`) o de orden superior (`F: for<'a> Fn(&'a str)`).
- `where Self: Sized` en un método de trait lo excluye de los objetos `dyn`, para que el resto del trait siga siendo compatible con `dyn`.
- Los límites se comprueban en **cada uso**: si el tipo concreto no los cumple, el error aparece donde se llama, señalando el límite incumplido.
