`for` recorre, uno a uno, los elementos de cualquier cosa que se pueda convertir en iterador.

## Sinopsis

```text
'etiqueta: for patrón in expresión { cuerpo }     // bucle (la etiqueta es opcional)
for<'a> F: Fn(&'a T)                             // límite de orden superior (HRTB)
impl Trait for Tipo                              // en implementaciones de traits (ver impl)
```

## Qué hace

### Uso 1 · Bucle `for`

`for x in e { … }` equivale, más o menos, a:

```text
let mut it = IntoIterator::into_iter(e);
loop {
    match it.next() {
        Some(x) => { … }
        None => break,
    }
}
```

Consecuencias:

- `for x in v` **mueve** `v` (llama a `into_iter`, que se queda con la propiedad).
- `for x in &v` presta `v`: los elementos son `&T`. `for x in &mut v` da `&mut T`.
- La parte entre `for` e `in` es un **patrón irrefutable**: `for (i, x) in …` desestructura.
- Un `for` siempre vale `()`; `break` no puede llevar valor dentro de él.

### Uso 2 · `for<'a>`: límites de orden superior

`for<'a>` dice «para **todo** tiempo de vida `'a`». `F: for<'a> Fn(&'a str) -> usize` exige una closure que acepte referencias de cualquier duración. Casi siempre el compilador lo deduce solo.

### Uso 3 · `impl Trait for Tipo`

Ver [`impl`](/ref/lenguaje/palabras-clave/impl/).

## Errores

<NoCompila ej="ref-lenguaje/kw-for-error" />

`error[E0382]: borrow of moved value: v`. La nota explica que el `for` se transforma en una llamada a `IntoIterator::into_iter`, que se queda con `v`. La ayuda propone `for x in &v`. Este error te protege de un **uso tras liberar**: el bucle destruyó el vector al terminar.

## Desde

Rust 1.0. `for` sobre arrays por valor (que dé `T` en vez de `&T`): edición 2021.
