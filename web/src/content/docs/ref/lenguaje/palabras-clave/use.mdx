`use` crea un **atajo**: después de `use std::collections::HashMap;` puedes escribir `HashMap` en vez de la ruta completa.

## Sinopsis

```text
use ruta::Nombre;
use ruta::{A, B, sub::C};        // varios, anidados
use ruta::{self, A};             // el módulo y A
use ruta::*;                     // glob: todo lo público
use ruta::Nombre as Otro;        // renombrar
use ruta::Trait as _;            // importar un trait sin ocupar su nombre
pub use ruta::Nombre;            // reexportar
fn f() -> impl Trait + use<'a, T>   // captura precisa (otro significado)
```

## Qué hace

### Uso 1 · Importar

`use` solo crea un nombre local; no copia código ni cambia la visibilidad del original. Puede ir en cualquier módulo o bloque, y afecta solo a ese ámbito. Los nombres importados con `*` tienen **menos prioridad** que los declarados o importados explícitamente.

Las rutas de `use` empiezan por el nombre de un crate (`std`, una dependencia), por `crate`, `self` o `super`, o por un nombre que ya esté en ámbito.

### Uso 2 · Reexportar

`pub use` hace que el elemento se vea **también** desde aquí. Las bibliotecas lo usan para ofrecer una API plana sin enseñar su estructura interna.

### Uso 3 · `use<…>` en `impl Trait`

En un tipo de retorno `impl Trait + use<'a, T>`, `use<…>` dice **qué** parámetros genéricos y tiempos de vida captura el tipo opaco. Ver [`impl`](/ref/lenguaje/palabras-clave/impl/).
