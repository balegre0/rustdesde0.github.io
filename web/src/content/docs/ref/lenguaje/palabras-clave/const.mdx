`const` marca cosas que se conocen **al compilar**. Tiene cinco usos.

## Sinopsis

```text
const NOMBRE: Tipo = expresión;            // constante
const fn f(…) -> T { … }                   // función evaluable al compilar
fn f<const N: usize>(…)                    // parámetro genérico constante
const { expresión }                        // bloque const (inline const)
*const T                                   // puntero crudo de solo lectura
&raw const lugar                           // crear un *const sin pasar por una referencia
```

## Qué hace

### Uso 1 · Constantes

`const N: u32 = 10;` define un valor que se calcula al compilar y se **copia** en cada sitio donde se usa. No tiene una dirección fija en memoria (para eso está `static`). El tipo es obligatorio. Por convención, el nombre va en MAYÚSCULAS.

### Uso 2 · `const fn`

Una `const fn` se puede llamar en un contexto constante (inicializar un `const`, la longitud de un array…) y también normalmente al ejecutar. Su cuerpo tiene límites: solo puede llamar a otras `const fn`, no puede reservar memoria en el montón, etc. Ver [Evaluación const](/ref/lenguaje/evaluacion-const/).

### Uso 3 · Genéricos constantes

`<const N: usize>` hace que un número forme parte del tipo, como la longitud de `[T; N]`. Hoy se admiten enteros, `bool` y `char`.

### Uso 4 · Bloques `const`

`const { … }` obliga a evaluar una expresión al compilar, en medio de código normal. Si la evaluación falla (por ejemplo, un `panic!`), el programa **no compila**.

### Uso 5 · Punteros `*const T`

El tipo de puntero crudo que no permite escribir a través de él. Leerlo con `*p` exige un bloque `unsafe`.

## Errores

<NoCompila ej="ref-lenguaje/kw-const-error" />

`error[E0015]: cannot call non-const function leer_numero in constants`. La solución es declarar la función como `const fn` (si su cuerpo lo permite).

## Desde

Constantes y `*const`: Rust 1.0. `const fn`: 1.31 (ampliadas en muchas versiones posteriores). Genéricos constantes: 1.51. Bloques `const`: 1.79. `&raw const`: 1.82.
