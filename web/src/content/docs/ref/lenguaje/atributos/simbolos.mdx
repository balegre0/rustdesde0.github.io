Estos atributos afectan al **nombre** o al **lugar** de una función o un `static` en el archivo objeto. Sirven para FFI, para embebido y para trucos de bajo nivel.

## Sinopsis

```text
#[unsafe(no_mangle)]                 // símbolo con el nombre tal cual
#[unsafe(export_name = "nombre")]    // símbolo con otro nombre
#[unsafe(link_section = ".datos")]   // en una sección concreta
#[used]                              // conservar un static aunque no se use
```

## Qué hace

- **`no_mangle`**: el compilador normalmente codifica los nombres (`_ZN4main5sumar17h…E`) para que no choquen. Con `no_mangle`, el símbolo se llama exactamente como la función: así otro lenguaje puede encontrarla. Implica que la función se exporta.
- **`export_name = "…"`**: como `no_mangle`, pero con el nombre que elijas.
- **`link_section = "…"`**: coloca la función o el `static` en una sección concreta del objeto (por ejemplo, la tabla de vectores de interrupción de un microcontrolador).
- **`used`**: obliga a conservar un `static` en el objeto aunque nada lo use (el enlazador puede descartarlo igualmente salvo que la sección también se conserve).

**Por qué son inseguros.** Dos símbolos con el mismo nombre en un programa son comportamiento indefinido, y un nombre como `malloc` o `memcpy` sustituiría al del sistema. El compilador no puede comprobarlo, así que desde la edición 2024 se escriben dentro de `unsafe(…)`:
