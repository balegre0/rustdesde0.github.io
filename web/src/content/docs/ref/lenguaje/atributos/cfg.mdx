`#[cfg(…)]` decide si un elemento **existe**. `#[cfg_attr(…)]` decide si se le **añaden** atributos.

## Sinopsis

```text
#[cfg(predicado)]
#[cfg_attr(predicado, atributo1, atributo2…)]

predicado: unix | windows | test | debug_assertions | true | false
         | target_os = "linux" | target_family = "wasm" | target_arch = "x86_64"
         | target_pointer_width = "64" | target_endian = "little"
         | target_feature = "avx2" | target_has_atomic = "64" | panic = "abort"
         | feature = "x" | all(…) | any(…) | not(…)
```

## Qué hace

- **`cfg`**: si el predicado es falso, el elemento se elimina **antes** de comprobar nombres y tipos, como si no estuviera escrito. Se aplica a elementos, campos, variantes, sentencias, expresiones de bloque y brazos de `match`.
- **`cfg_attr`**: si el predicado es verdadero, se comporta como si escribieras los atributos de la lista. Muy usado con `derive` opcionales (`#[cfg_attr(feature = "serde", derive(Serialize))]`) y con `windows_subsystem`.
- La macro **`cfg!(…)`** evalúa el mismo predicado como un `bool`, sin eliminar código.

Desde 1.80, los nombres y valores de `cfg` se comprueban (`--check-cfg`): un nombre mal escrito da el aviso `unexpected_cfgs`.
