`#[target_feature(enable = "…")]` permite que una función use instrucciones que no todas las CPU de esa familia tienen.

## Sinopsis

```text
#[target_feature(enable = "avx2")]
#[target_feature(enable = "avx2,fma")]
fn f() { … }
```

## Qué hace

El compilador genera la función como si la CPU tuviera esas extensiones: puede vectorizar con AVX2, usar `popcnt`, etc. El resto del programa sigue siendo compatible con CPU antiguas.

Ejecutar esa función en una CPU **sin** la extensión es **comportamiento indefinido** (normalmente, «instrucción ilegal»). Por eso:

- Desde 1.86, una función segura puede llevar `#[target_feature]`, pero **llamarla** desde código que no tiene esa extensión activada requiere `unsafe`.
- Antes de llamarla, se comprueba la CPU: `is_x86_feature_detected!("avx2")` (o `std::arch::is_aarch64_feature_detected!`).

La alternativa sin `unsafe` es compilar **todo** el programa para una CPU concreta: `-C target-cpu=native` (solo para tu máquina) o `-C target-feature=+avx2`.
