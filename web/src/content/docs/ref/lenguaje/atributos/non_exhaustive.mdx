`#[non_exhaustive]` declara: «a este tipo le pueden salir campos o variantes nuevos en el futuro».

## Sinopsis

```text
#[non_exhaustive] pub struct Config { pub hilos: u32 }
#[non_exhaustive] pub enum Error { Red, Disco }
pub enum E { #[non_exhaustive] Variante { x: u8 } }
```

## Qué hace

Solo tiene efecto **en otros crates** (dentro del tuyo, no cambia nada):

- **En un enum**: un `match` sobre él tiene que llevar un brazo `_` (o un patrón comodín), aunque cubra todas las variantes actuales.
- **En un struct o una variante**: no se puede construir con la sintaxis `Config { hilos: 4 }`, ni desmontar sin `..`. Hay que usar las funciones que ofrezca el crate.

Así, la biblioteca puede añadir variantes o campos en una versión **menor** sin romper el código de nadie. `std::io::ErrorKind` es `#[non_exhaustive]`.
