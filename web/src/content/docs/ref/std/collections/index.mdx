## Contenido de un vistazo

| Nombre | Resumen | Desde |
|---|---|---|
| [`HashMap`](/ref/std/collections/hashmap/) | Diccionario clave → valor, sin orden. Lo normal para buscar por clave. | 1.0 |
| [`HashSet`](/ref/std/collections/hashset/) | Conjunto sin repetidos, sin orden. | 1.0 |
| [`BTreeMap`](/ref/std/collections/btreemap/) | Diccionario **ordenado** por clave. | 1.0 |
| `BTreeSet` | Conjunto ordenado. | 1.0 |
| [`VecDeque`](/ref/std/collections/vecdeque/) | Cola de doble extremo: meter y sacar por los dos lados. | 1.0 |
| [`BinaryHeap`](/ref/std/collections/binaryheap/) | Cola de prioridad: siempre sale el mayor. | 1.0 |
| `LinkedList` | Lista doblemente enlazada. Casi nunca es la mejor opción. | 1.0 |

## Conceptos clave

| Necesitas… | Usa | Coste típico |
|---|---|---|
| una lista en orden de llegada | `Vec` | acceso por índice O(1) |
| buscar por clave, el orden da igual | `HashMap` | O(1) de media |
| buscar por clave y recorrer en orden | `BTreeMap` | O(log n) |
| saber si algo ya apareció | `HashSet` | O(1) de media |
| una cola (FIFO) | `VecDeque` | O(1) por los dos extremos |
| sacar siempre el mayor (o el menor) | `BinaryHeap` | O(log n) |

- **Claves**: `HashMap` y `HashSet` piden que la clave implemente `Hash` y `Eq`; `BTreeMap` y `BTreeSet`, que implemente `Ord`. Con `#[derive(Hash, PartialEq, Eq)]` (o `PartialOrd, Ord`) tus tipos sirven de clave.
- **El orden de un HashMap no está definido** y cambia entre ejecuciones: no dependas de él.
