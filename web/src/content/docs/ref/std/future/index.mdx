**Ruta:** `std::future, std::task`

## Para qué sirve

Un **future** es un cálculo que quizá todavía no ha terminado. Una `async fn` devuelve un future; `.await` espera a otro future dentro de un `async`. Pero un future **no hace nada solo**: alguien (un **ejecutor**) tiene que llamar a su método `poll` repetidamente. Cada `poll` devuelve `Poll::Ready(valor)` si terminó o `Poll::Pending` si aún no; en ese caso, el future guarda el `Waker` del `Context` para avisar cuando valga la pena volver a sondearlo.

La biblioteca estándar define estas piezas pero **no incluye un ejecutor completo**: normalmente se usa uno de un crate (como Tokio). El ejemplo construye uno mínimo con `Waker::noop()` (estable desde Rust 1.85).

## Conceptos clave

- **Perezosos**: crear un future (llamar a una `async fn`) no ejecuta nada hasta el primer `poll`.
- **Máquina de estados**: el compilador convierte cada `async fn` en un tipo que guarda en qué `.await` se quedó y las variables vivas en ese punto.
- **[E0728](/errores/e0728/)**: `.await` solo dentro de `async`.

## Sinopsis

```rust
pub trait Future {
    type Output;

    // Required method
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

pub enum Poll<T> {
    Ready(T),
    Pending,
}
```
