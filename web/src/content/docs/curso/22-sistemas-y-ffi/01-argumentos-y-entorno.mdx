Un programa de terminal recibe información de dos sitios antes de empezar: los **argumentos** que escribes tras su nombre (`grep hola notas.txt`) y las **variables de entorno** del sistema (`PATH`, `HOME`, `LANG`…). Aquí aprendes a leer las dos cosas de forma robusta.

## La idea

`std::env::args()` devuelve un **iterador** de `String`. El primero suele ser el nombre del programa, así que lo normal es saltarlo con `.skip(1)`. Como es un iterador, puedes recogerlo en un `Vec`, buscar con `.nth(i)` o recorrerlo con `for`. Si un argumento puede no ser UTF-8 válido (rutas raras en algunos sistemas), existe `args_os()`, que da `OsString` (lección 7).

Los argumentos **pueden faltar**: nunca hagas `.unwrap()` a ciegas en un programa que va a usar otra persona. Usa `Option` con un valor por defecto o un mensaje de uso. Para programas serios, el crate `clap` genera el análisis de argumentos, la ayuda (`--help`) y los errores.

Las variables de entorno se leen con `std::env::var(nombre)`, que devuelve `Result<String, VarError>`. `env::vars()` las recorre todas. Puedes cambiar variables del **propio** proceso con `env::set_var`, pero en la edición 2024 esa función es `unsafe`: si otro hilo lee el entorno a la vez, el sistema operativo puede leer memoria ya liberada.

## Pruébalo

En el navegador el programa arranca **sin argumentos y sin variables de entorno**, así que verás los valores por defecto. En tu PC prueba `cargo run -- Ana` y, en PowerShell, `$env:IDIOMA = "es"; cargo run`.

## Bajo el capó

<BajoElCapo>

**De dónde salen.** Cuando el sistema operativo arranca tu programa le entrega los argumentos y el entorno. En Linux llegan en la pila inicial del proceso; en Windows llegan como **una sola cadena** de línea de órdenes que el runtime de Rust trocea siguiendo las reglas de comillas de Windows. Todo eso ocurre en el `main` de verdad, el que genera rustc antes de llamar a tu `fn main` (lo verás en la lección 10 al quitarlo con `#![no_main]`).

**En el navegador** el programa es WebAssembly con WASI: el «sistema operativo» es un pequeño entorno en JavaScript que le pasa una lista de argumentos y un entorno vacío. Por eso la salida dice `hay 0 variables de entorno`.

**`set_var` es `unsafe` en 2024.** En la edición 2024, `std::env::set_var` y `remove_var` son funciones `unsafe`. El motivo es la seguridad de memoria, no el estilo: en varios sistemas, el entorno es una estructura global que otras funciones del sistema leen sin protección. Modificarla mientras otro hilo la lee es una **carrera de datos**.

</BajoElCapo>

## Trampa típica

<Trampa titulo="`args().nth(1).unwrap()` en un programa para otros">

❌ `let archivo = std::env::args().nth(1).unwrap();` → si se ejecuta sin argumentos, el pánico dice `called Option::unwrap() on a None value`, que no ayuda a nadie.

✅ Explica qué falta y sal con un código de error:

```rust
let Some(archivo) = std::env::args().nth(1) else {
    eprintln!("uso: contar <archivo>");
    std::process::exit(2);
};
```

</Trampa>
