Cada `Vec`, `String` y `Box` de tu programa pide memoria al **asignador global**. Puedes sustituirlo por uno tuyo: para medir, para depurar o porque no hay sistema operativo que te dé uno.

## La idea

Un asignador es un tipo que implementa el trait **`GlobalAlloc`**, marcado con `#[global_allocator]` sobre un `static`:

```rust
unsafe impl GlobalAlloc for MiAsignador {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 { … }
    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) { … }
}

#[global_allocator]
static GLOBAL: MiAsignador = MiAsignador;
```

El `Layout` dice **cuántos bytes** y con qué **alineación**. El asignador promete devolver un puntero a un bloque de ese tamaño, alineado, que nadie más esté usando (o un puntero nulo si no hay memoria). Es `unsafe` porque nadie puede comprobar esa promesa por ti.

## Bajo el capó

<BajoElCapo>

**El asignador lo usa todo.** También `std` por dentro: el búfer de `stdout`, los nombres de los hilos… Por eso el *bump* lleva repartidos más bytes de los que reservó tu código. Y por eso un asignador **nunca** debe reservar memoria a través de sí mismo (por ejemplo, con `println!` dentro de `alloc`): entraría en un bucle infinito.

**Por qué `compare_exchange_weak` en un bucle.** Dos hilos pueden pedir memoria a la vez. Cada uno calcula su trozo a partir de `siguiente` y trata de avanzarlo con un `compare_exchange`; si otro se le adelantó, vuelve a calcular con el valor nuevo. La versión `weak` puede fallar sin motivo en algunos procesadores, pero dentro de un bucle no importa y es más barata.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Olvidar la alineación">

❌ Devolver `base + siguiente` sin redondear. Un `Vec<u64>` recibiría una dirección impar, y crear referencias a sus elementos sería comportamiento indefinido (y en algunos procesadores, un fallo inmediato).

✅ Redondea **la dirección** (no el desplazamiento) al `layout.align()` antes de entregarla.

</Trampa>
