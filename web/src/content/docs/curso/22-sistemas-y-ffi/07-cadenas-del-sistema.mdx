`String` es el texto de Rust: UTF-8 y con su longitud guardada. Pero el sistema operativo y las bibliotecas externas no siempre hablan así. Rust tiene tipos específicos para esas fronteras, y elegir bien evita errores sutiles.

## La idea

Hay **dos parejas** nuevas, igual que `String`/`&str` o `PathBuf`/`&Path` (con propiedad / prestado):

- **`CString` / `&CStr`**: bytes **terminados en 0** y sin ningún 0 dentro. Es el formato de texto del **ABI de C**, el que usan casi todas las bibliotecas del sistema y muchas externas. Una función de ese mundo recibe un puntero al primer byte y lee hasta encontrar el 0; no recibe la longitud.
- **`OsString` / `&OsStr`**: texto en el formato nativo del sistema operativo. En Unix son bytes cualquiera; en Windows, una codificación de 16 bits que admite secuencias que no son UTF-16 válido. Los nombres de archivo, los argumentos (`args_os`) y las variables de entorno (`var_os`) pueden no ser UTF-8, y `OsString` los guarda sin perder nada.

Desde Rust 1.77 puedes escribir un `&CStr` literal con `c"texto"`: el compilador añade el 0 final y comprueba que no haya ninguno dentro.

Conversiones: `CString::new(texto)` falla si hay un 0 interior; `cstr.to_str()` falla si no es UTF-8; `os.to_str()` devuelve `None` si no es UTF-8, y `to_string_lossy()` sustituye lo inválido por `�`.

## Bajo el capó

<BajoElCapo>

**Tamaños y punteros.** Un `&str` es un puntero gordo (puntero + longitud). Un `&CStr` hoy también lo es en la implementación, pero el **contrato** es el de las funciones externas: lo que se pasa por la frontera es `cstr.as_ptr()`, un `*const c_char` al primer byte, y quien lo recibe busca el 0 para saber dónde acaba. Por eso el 0 interior está prohibido: partiría la cadena en silencio.

**Vida de los punteros.** Este es el error clásico en la frontera:

```rust
let p = CString::new("hola").unwrap().as_ptr(); // el CString temporal se destruye al final de la línea
// usar p aquí sería un uso tras liberar
```

El `CString` es temporal y se libera al acabar la sentencia; `p` queda colgando. Compila (un puntero crudo no tiene lifetime), pero usarlo es comportamiento indefinido. Guarda el `CString` en una variable que viva mientras se use el puntero. El compilador avisa de este patrón concreto con la lint `dangling_pointers_from_temporaries`.

**Windows.** En Windows las API «W» reciben texto de 16 bits terminado en 0. `std::os::windows::ffi::OsStrExt::encode_wide` convierte un `OsStr` a esa forma (verás `windows-sys` en la lección 12).

</BajoElCapo>
