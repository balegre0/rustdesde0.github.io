Un programa de sistemas a menudo **coordina** otros programas: un compilador que llama al enlazador, un script de build que ejecuta tests, un editor que lanza un formateador. `std::process` es la forma segura de hacerlo.

## La idea

`std::process::Command` es un **constructor** (*builder*): `Command::new("programa")` y luego, encadenados, `.arg("…")` o `.args([...])`, `.env("CLAVE", "valor")`, `.current_dir(ruta)`, y cómo conectar su entrada y salida (`.stdin(Stdio::piped())`…). Al final, una de tres:

- `.output()`: ejecuta, **espera** y te da un `Output` con `status`, `stdout` y `stderr` como `Vec<u8>`.
- `.status()`: ejecuta y espera; la salida del hijo va directamente a tu terminal.
- `.spawn()`: arranca el proceso y vuelve al momento con un `Child`, con el que puedes escribirle, leer de él o esperar con `.wait()`.

Cada argumento viaja **por separado**: `.arg("mi archivo.txt")` es un solo argumento con un espacio dentro, nunca dos. No hay una terminal intermedia interpretando el texto, así que no hay inyección de órdenes.

Para terminar **tu** programa con un código concreto, devuelve `std::process::ExitCode` desde `main` (`ExitCode::SUCCESS`, `ExitCode::FAILURE` o `ExitCode::from(n)`). Existe también `std::process::exit(n)`, pero corta en seco: los `Drop` pendientes **no se ejecutan** (un `BufWriter` sin vaciar perdería su contenido).

## Pruébalo

En tu PC, un ejemplo completo que sí funciona (verificado que compila con `rustc --emit=metadata`):

```rust
use std::process::Command;

fn main() -> std::io::Result<()> {
    let salida = Command::new("rustc").arg("--version").output()?;
    println!("¿éxito? {}", salida.status.success());
    println!("dice: {}", String::from_utf8_lossy(&salida.stdout).trim());
    Ok(())
}
```

Salida típica: `¿éxito? true` y la versión de tu `rustc`.

## Bajo el capó

<BajoElCapo>

**Cómo se crea un proceso.** En Linux y macOS, `spawn` usa las llamadas `fork`/`exec` (o `posix_spawn` cuando puede): se crea un proceso hijo y se sustituye su programa por el nuevo. En Windows se usa `CreateProcessW`, que recibe **una sola cadena** con toda la línea de órdenes; la biblioteca estándar construye esa cadena **escapando** cada argumento con las reglas de Windows para que el hijo los separe igual que tú los diste.

**El caso `.bat`.** Los archivos por lotes de Windows (`.bat`, `.cmd`) se ejecutan a través de `cmd.exe`, que tiene sus propias reglas de interpretación. En 2024 se publicó un aviso de seguridad (CVE-2024-24576) porque ciertos argumentos podían inyectar órdenes al lanzar un `.bat`; Rust 1.77.2 endureció el escapado y, si no puede pasarlos de forma segura, devuelve un error en vez de ejecutar.

**Códigos de salida.** `ExitStatus::success()` es `true` si el código es 0. `status.code()` devuelve `Option<i32>`: en Unix, un proceso matado por una señal no tiene código, así que es `None`.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Lanzar «una línea de órdenes» como un solo argumento">

❌ `Command::new("git commit -m arreglo")` busca un programa que se llame literalmente `git commit -m arreglo`, y falla con `NotFound`.

✅ El programa va en `new` y cada argumento en su `.arg`: `Command::new("git").args(["commit", "-m", "arreglo"])`. Si de verdad necesitas una terminal (tuberías, comodines), lánzala explícitamente y piensa en la seguridad de lo que le pasas.

</Trampa>
