En el mundo 05 te quedó una pregunta abierta: la pila se limpia sola, pero **¿quién devuelve la memoria del heap, y cuándo?** Este mundo es la respuesta de Rust, y es la idea que lo hace distinto: la **propiedad** (*ownership*).

Te lo decimos claro: este es el mundo donde más gente se atasca. Es normal. Por eso está partido en lecciones cortas, cada una con **una sola idea**, y cada regla viene con **el error de memoria que evita**. Al borrow checker se le gana entendiéndolo, no peleando con él.

## Cómo leer las tablas de permisos

En muchas lecciones verás una tabla como esta. Cada fila es una línea del programa y muestra qué puede hacer cada variable **después** de esa línea:

- **R** (*read*): puedes **leer** el valor.
- **W** (*write*): puedes **modificarlo**.
- **O** (*own*): eres su **dueño**: puedes **moverlo** a otro sitio o **liberarlo**.
- Un **`-`** en una posición significa que ese permiso no está (o se ha perdido).

Así, `RWO` es «lo puedo todo», `R-O` es «soy dueño pero no puedo modificarlo» (la variable no es `mut`) y `---` es «ya no puedo usarla». El compilador comprueba estos permisos en cada línea; cuando una línea necesita un permiso que no tienes, no compila.

## Lo que el compilador vigila en este mundo

| Error | Qué te impide hacer | Qué fallo de memoria evita |
|---|---|---|
| [E0382](/errores/e0382/) | Usar una variable cuyo valor ya se movió | Uso tras liberar y doble liberación |
| [E0507](/errores/e0507/) | Sacar (mover) un valor de dentro de algo que no posees | Que un `Vec` libere un elemento que ya no es suyo |
| [E0184](/errores/e0184/) | Que un tipo con `Drop` sea `Copy` | Doble liberación de un recurso |
| [E0425](/errores/e0425/) | Nombrar una variable fuera de su ámbito | Usar algo que ya se liberó |
