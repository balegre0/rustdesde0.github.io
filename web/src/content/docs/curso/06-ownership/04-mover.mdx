## La idea

`let s2 = s1;` no hace una copia del texto. Hace un **movimiento** (*move*): la propiedad pasa de `s1` a `s2`. Desde ese momento:

- `s2` es la dueña, con los permisos que tenía `s1`.
- `s1` **pierde todos sus permisos**. Sigue escrita en tu código, pero el compilador no te deja leerla, modificarla ni moverla: ya no es dueña de nada.

Recuerda la regla 2: **un solo dueño a la vez**. Si `s1` siguiera siendo dueña, al final de `main` habría dos liberaciones del mismo texto. Mover es la forma de cumplir la regla sin copiar nada caro.

Lo que se mueve físicamente es la **ficha** de la pila (puntero, capacidad, longitud). El texto en el heap se queda donde estaba; simplemente lo señala otra variable.

¿Y cuánto ocupa la ficha que se copia? Compruébalo:

<Ejecutar ej="m06/tamano-string" />

En el navegador, un `usize` mide 4 bytes, así que la ficha mide 12. En un PC de 64 bits mide 24. Mover un `String` copia **siempre** esos 12 o 24 bytes, tenga el texto 4 bytes o un millón.

## Bajo el capó

<BajoElCapo>

**El dibujo de memoria** (64 bits, direcciones de ejemplo):

```text
ANTES de let s2 = s1;                DESPUÉS
  PILA                                 PILA
  s1 ┌──────────────┐                  s1 ┌──────────────┐  (sin permisos:
     │ ptr  ────────┼──┐                  │ ptr  ────────┼─┐  el compilador
     │ cap  4       │  │                  │ cap  4       │ │  no deja usarla)
     │ len  4       │  │                  │ len  4       │ │
     └──────────────┘  │                  └──────────────┘ │
                       │               s2 ┌──────────────┐ │
                       │                  │ ptr  ────────┼─┤
                       │                  │ cap  4       │ │
                       │                  │ len  4       │ │
                       │                  └──────────────┘ │
  HEAP                 ▼               HEAP                ▼
       ┌───┬───┬───┬───┐                    ┌───┬───┬───┬───┐
       │ h │ o │ l │ a │                    │ h │ o │ l │ a │
       └───┴───┴───┴───┘                    └───┴───┴───┴───┘
```

Fíjate en algo importante: **los bytes de `s1` siguen ahí**, con el mismo puntero. Mover no borra nada. Lo que cambia es lo que el compilador **te deja hacer**. «Invalidar» `s1` es una decisión del compilador, no una operación en memoria.

**Lo que dice el MIR.** En el MIR de un programa así, el movimiento es una línea explícita y solo hay **una** liberación, la de `s2`:

```text
        _2 = move _1;
        ...
        drop(_2) -> [return: bb3, unwind continue];
```

No existe ningún `drop(_1)`: como `s1` (`_1`) entregó su propiedad, el compilador no la libera. Si existieran los dos `drop`, el texto se liberaría dos veces.

**Mover es copiar bytes de pila.** El ensamblador de un movimiento es copiar la ficha a otro sitio (y a menudo el optimizador ni eso: usa directamente el mismo hueco). Mover un `String` de un millón de bytes cuesta lo mismo que mover uno de 4:

## Trampa típica

<Trampa titulo="Leer el error de abajo arriba">

E0382 siempre cuenta la historia en tres marcas. Léelas en orden:

1. `move occurs because s1 has type String, which does not implement the Copy trait`: por qué se mueve (en la lección 6 verás qué tipos **no** se mueven, sino que se copian).
2. `value moved here`: **dónde** perdió `s1` la propiedad.
3. `value borrowed here after move`: dónde intentaste usarla después.

❌ Aplicar el `help:` sin pensar: «consider cloning the value» (`s1.clone()`) arregla el error, pero **duplica** el texto en el heap. A veces es lo correcto; muchas veces no hace falta.

✅ Primero pregúntate: ¿necesito de verdad dos textos? Si no, usa la dueña nueva (`s2`), como en el arreglo de arriba. En el mundo 07 aprenderás la tercera vía: **prestar** sin mover.

</Trampa>
