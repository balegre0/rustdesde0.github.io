## La idea

El compilador tiene que conocer el **tamaño** de cada tipo al compilar, porque reserva sitio en la pila para cada variable. Para un `enum`, el tamaño es el de su variante más grande (más la etiqueta). Si una variante contiene **el mismo tipo entero**, la cuenta se convierte en «tamaño de Lista = 4 + tamaño de Lista», que no tiene solución. Eso es el error **E0072**: *recursive type has infinite size*.

La salida es la **indirección**: en lugar de guardar el siguiente nodo dentro, guardas **dónde está**. Una `Box<Lista>` siempre mide lo mismo (un puntero), da igual lo larga que sea la lista. Ahora la cuenta sí cierra: tamaño de Lista = `i32` + puntero (+ etiqueta, si hace falta).

Este es el uso más característico de `Box`: tipos que se definen en términos de sí mismos, como listas, árboles o las expresiones de una calculadora (`Suma(Box<Expr>, Box<Expr>)`).

## Pruébalo

<Ejecutar ej="m15/lista-box" />

En el navegador la lista mide 8 bytes (4 del `i32` y 4 del puntero). En x86-64 mide 16, comprobado con `size_of`.

## Bajo el capó

<BajoElCapo>

La lista `1 → 2 → 3` queda así: solo el primer nodo vive en la pila; los demás, en el heap, cada uno apuntando al siguiente.

```text
PILA                         HEAP
┌───────────────────┐        ┌───────────────────┐        ┌───────────────────┐        ┌────────┐
│ l: Nodo(1, ●──────┼───────►│ Nodo(2, ●─────────┼───────►│ Nodo(3, ●─────────┼───────►│ Vacia  │
└───────────────────┘        └───────────────────┘        └───────────────────┘        └────────┘
```

¿Dónde está la etiqueta que distingue `Nodo` de `Vacia`? En ningún sitio: `Vacia` no lleva datos, así que el compilador la representa con un puntero nulo, que una Box nunca puede ser (el **nicho** de la lección anterior). Por eso `Lista` mide exactamente `i32` + puntero, con relleno de alineación: 16 bytes en x86-64.

La función `suma` es recursiva igual que el tipo: cada llamada ocupa un **marco de pila** (mundo 5). Una lista de millones de nodos podría desbordar la pila al recorrerla así; con un bucle `while let` no pasaría. Además, al liberar la lista, cada `Box` libera a la siguiente de forma recursiva: con listas enormes eso también puede agotar la pila.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Poner Box donde ya hay un contenedor">

❌ Pensar que todo tipo recursivo necesita `Box`:

```rust
struct Arbol {
    valor: i32,
    hijos: Vec<Box<Arbol>>, // la Box sobra
}
```

✅ Un `Vec` ya guarda sus elementos en el heap, así que rompe la recursión por sí solo:

```rust
struct Arbol {
    valor: i32,
    hijos: Vec<Arbol>, // compila: Arbol mide 32 bytes en x86-64
}
```

La versión con `Box` funciona, pero añade una reserva y un salto por cada hijo sin ganar nada.

</Trampa>
