## La idea

Rust promete que, en código seguro, nunca habrá **comportamiento indefinido** (UB): ni uso tras liberar, ni doble liberación, ni carreras de datos. Lo que **no** promete es que toda la memoria se libere. Una **fuga** es memoria que sigue reservada aunque ya nadie la use: desperdicia recursos, pero no corrompe nada ni deja leer basura.

Por eso existen funciones **seguras** para fugar a propósito. `std::mem::forget(x)` toma `x` y no ejecuta su `Drop`. `Box::leak(b)` hace algo más útil: suelta la Box y te devuelve una referencia `&'static mut T`, que vale **durante todo el programa** porque esa memoria ya no se liberará nunca. Es la forma limpia de crear en ejecución datos que deben vivir para siempre, como una configuración leída al arrancar.

La consecuencia de diseño es profunda: **ningún código puede confiar en que un `Drop` llegue a ejecutarse** para mantener la seguridad. Un `Drop` sirve para limpiar, no para garantizar que no haya UB. Quien diseña tipos con `unsafe` por dentro tiene que contar con que alguien haga `forget` de su valor.

## Bajo el capó

<BajoElCapo>

`mem::forget` está implementado envolviendo el valor en `ManuallyDrop<T>`, un tipo que le dice al compilador «no insertes el `drop` de esto». Los bytes del valor desaparecen de la pila sin que nadie llame al destructor; si poseía memoria del heap, esa memoria queda reservada y sin dueño.

`Box::leak` hace lo mismo con la Box y convierte su puntero en una referencia:

```text
antes:   PILA: b: Box<String> ●──► HEAP: String
después: PILA: config: &'static mut String ●──► HEAP: String   (sin dueño; nunca se libera)
```

Las tres formas de fugar desde código seguro:

| Cómo | Qué queda |
|---|---|
| `mem::forget(x)` | el `Drop` de `x` no se ejecuta |
| `Box::leak(b)` | una `&'static mut T` al heap |
| un ciclo de `Rc` | valores que se mantienen vivos entre sí |

Al acabar el proceso, el sistema operativo recupera toda su memoria. Una fuga solo es un problema real en programas que se ejecutan mucho tiempo (servidores, juegos) y fugan una y otra vez.

</BajoElCapo>

<Historia titulo="La «leakpocalypse» de 2015">

Pocas semanas antes de Rust 1.0 se descubrió que una API de la biblioteca estándar para hilos con préstamos confiaba en que un `Drop` se ejecutara siempre. Con un ciclo de `Rc` se podía impedir ese `Drop` y provocar un uso tras liberar desde código seguro. La decisión fue de principio: se aceptó que fugar es seguro, `mem::forget` dejó de ser `unsafe` y aquella API se retiró. Años después volvió con un diseño que no depende de `Drop`: `std::thread::scope` (mundo 17).

</Historia>

## Trampa típica

<Trampa titulo="Usar Box::leak para callar al borrow checker">

❌ Fugar un `String` en un bucle solo porque el compilador pedía un `&'static str`:

```rust
for linea in lineas {
    let nombre: &'static str = Box::leak(linea.into_boxed_str()); // fuga en cada vuelta
    guardar(nombre);
}
```

✅ Si el dato no tiene que vivir todo el programa, cambia el diseño: guarda `String` (propietario) en lugar de `&'static str`. `Box::leak` es para un puñado de valores que viven hasta el final, no para cada iteración.

</Trampa>
