## La idea

Cuando llamas a un closure, ¿qué necesita de sí mismo para ejecutarse? Hay tres respuestas, y cada una es un trait:

| Trait | El cuerpo… | Para llamarlo hace falta | Se puede llamar |
|---|---|---|---|
| `Fn` | solo lee lo capturado | `&self` (préstamo compartido) | muchas veces, incluso a la vez |
| `FnMut` | modifica lo capturado | `&mut self` (préstamo exclusivo) | muchas veces, de una en una |
| `FnOnce` | consume lo capturado | `self` (el closure entero) | una vez |

**No eliges tú**: el compilador mira el cuerpo y le implementa al closure todos los traits que puede. Un closure que solo lee es `Fn`, y por eso también `FnMut` y `FnOnce`. Uno que modifica es `FnMut` y `FnOnce`. Uno que mueve algo hacia fuera (como `move || regalo`, que devuelve la `String`) solo es `FnOnce`: tras la primera llamada, el regalo ya no está.

Quien **recibe** un closure elige qué pide. Y la regla de oro es al revés de lo que parece: **pedir menos acepta más**. Una función con `F: FnOnce` acepta cualquier closure; una con `F: Fn` solo los más «tranquilos». Si vas a llamar al closure una sola vez, pide `FnOnce`; si lo llamas en un bucle, `FnMut`; si lo necesitas desde varios sitios a la vez, `Fn`.

## Bajo el capó

<BajoElCapo>

Los tres traits están en la biblioteca estándar y forman una escalera de **supertraits**: `trait FnMut: FnOnce` y `trait Fn: FnMut`. Simplificando (la firma real usa una tupla de argumentos y es inestable implementarlos a mano):

```rust
trait FnOnce<Args> {
    type Output;
    fn call_once(self, args: Args) -> Self::Output;      // se consume
}
trait FnMut<Args>: FnOnce<Args> {
    fn call_mut(&mut self, args: Args) -> Self::Output;  // préstamo exclusivo
}
trait Fn<Args>: FnMut<Args> {
    fn call(&self, args: Args) -> Self::Output;          // préstamo compartido
}
```

`f()` es azúcar para una de esas tres llamadas. Por eso un `FnMut` necesita `let mut f`: `call_mut` pide `&mut self`, y no se puede tomar un préstamo exclusivo de una variable que no es `mut` (E0596, como con cualquier método `&mut self`). Y por eso un `FnOnce` no se puede llamar dos veces: `call_once(self)` **mueve** el closure, y usarlo después es un uso tras mover (E0382).

Las funciones `fn` normales y los closures sin capturas implementan los tres traits, y además se convierten en **punteros a función** `fn(i32) -> i32` (8 bytes en un PC de 64 bits: solo la dirección del código).

</BajoElCapo>
