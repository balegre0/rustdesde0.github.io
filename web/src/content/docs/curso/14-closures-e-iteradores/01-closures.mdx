## La idea

Una función normal se declara con `fn`, tiene nombre y solo ve sus parámetros. Un closure se escribe **donde lo necesitas**, con los parámetros entre barras verticales:

```rust
let doble = |x| x * 2;          // parámetro x, cuerpo x * 2
let suma = |a: i32, b: i32| a + b;   // con tipos
let largo = |s: &str| -> usize { s.len() };   // con bloque y tipo de retorno
```

Se llama igual que una función: `doble(21)`. Los tipos son opcionales porque el compilador los **infiere** (deduce) del uso. Pero solo una vez: el primer uso fija el tipo para siempre.

Lo que lo hace especial es la **captura** (*capture*): dentro del cuerpo puedes nombrar variables que existían antes, como `iva` en el ejemplo. El closure se las lleva consigo. Una `fn` no puede hacerlo. Esa es la «memoria» del título, y en la lección siguiente verás exactamente cómo la guarda.

## Bajo el capó

<BajoElCapo>

Un closure **no es** un puntero a código. Es un **struct anónimo** que el compilador inventa para ti: sus campos son las variables capturadas, y además el compilador le implementa un trait de llamada (`Fn`, `FnMut` o `FnOnce`, lección 3). Cada closure que escribes tiene **su propio tipo**, distinto de todos los demás, aunque el código sea idéntico.

Por eso su tamaño depende de lo que capture. Lo medimos de verdad:

<Ejecutar ej="m14/tamano-closures" />

En el navegador (wasm32) un puntero mide 4 bytes. En un PC de 64 bits lo comprobamos con aserciones que el compilador evalúa al compilar: sin capturas, 0 bytes; capturando un `u64` por referencia, 8 (un puntero); moviendo el `u64`, 8; moviendo una `String`, 24 (puntero, capacidad y longitud).

Un closure sin capturas ocupa **cero bytes**: llamar a `doble(21)` no lee nada de memoria, el compilador sabe a qué código saltar solo por el tipo.

</BajoElCapo>
