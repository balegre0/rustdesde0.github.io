## La idea

Para que tu tipo sea un iterador, necesitas dos cosas: un **estado** (dónde vas) y un `next()` que entregue el siguiente valor y avance. El trait `Iterator` tiene decenas de métodos más, pero todos tienen implementación **por defecto** escrita en función de `next()`. Implementas uno y te regalan el resto: `map`, `filter`, `zip`, `sum`, `collect`…

Cuando el iterador es sencillo, ni siquiera hace falta un struct. Hay atajos que lo fabrican desde un closure:

- **`iter::from_fn(f)`**: cada `next()` llama a tu closure `f` (un `FnMut`, porque cambia su estado capturado) y entrega lo que devuelva. `None` termina.
- **`iter::successors(primero, f)`**: cada elemento sale del anterior aplicando `f`.
- **`iter::repeat(x)`** (infinito), **`iter::once(x)`** (uno solo) y **`iter::empty()`** (ninguno).

## Bajo el capó

<BajoElCapo>

Un método por defecto es una función genérica escrita una vez en la biblioteca estándar. Por ejemplo, `count` es, en esencia:

```rust
fn count(self) -> usize {
    let mut n = 0;
    let mut it = self;
    while let Some(_) = it.next() { n += 1; }
    n
}
```

Cuando llamas `CuentaAtras { actual: 10 }.filter(…).sum()`, el compilador monomorfiza `filter` y `sum` para **tu** tipo, con **tu** `next()` dentro: el mismo coste cero de la lección anterior. Muchos adaptadores se pueden especializar implementando métodos extra (por ejemplo `size_hint`, que dice cuántos elementos quedan y ayuda a `collect` a reservar memoria de una vez).

`from_fn` devuelve un `FromFn<F>`: un struct que guarda tu closure y cuyo `next()` es simplemente llamarlo. El estado del iterador son **las capturas del closure**: en el ejemplo, `a` y `b`, movidas dentro con `move`.

Un detalle de diseño: después de devolver `None`, el trait no obliga a seguir devolviendo `None`. Si lo necesitas garantizado, `.fuse()` lo asegura.

</BajoElCapo>
