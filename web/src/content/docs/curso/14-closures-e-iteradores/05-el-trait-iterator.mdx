## La idea

Un iterador es cualquier cosa que implemente este trait (la versión real tiene muchísimos métodos más, todos con implementación por defecto):

```rust
trait Iterator {
    type Item;                                   // qué tipo entrega
    fn next(&mut self) -> Option<Self::Item>;    // el siguiente, o None si se acabó
}
```

Eso es todo el contrato: **cada vez que llamas a `next()`, te da el siguiente elemento envuelto en `Some`, o `None` si ya no quedan**. Pide `&mut self` porque avanzar cambia su estado interno (por dónde va).

Lo importante es la **pereza** (*laziness*): crear un iterador, o encadenarle un `map`, no recorre nada. Solo se trabaja cuando alguien **consume** el iterador llamando a `next()`: un `for`, `sum`, `collect`, `count`… Esto tiene dos ventajas. No se crean listas intermedias. Y puedes trabajar con iteradores **infinitos** como `1..` (todos los números desde el 1) siempre que al final solo pidas unos pocos.

## Bajo el capó

<BajoElCapo>

El `for` es **azúcar sintáctico**. El compilador lo reescribe así (lo ves casi igual en el paso 2 del ejemplo):

```rust
let mut it = IntoIterator::into_iter(algo);
loop {
    match it.next() {
        Some(x) => { /* cuerpo del for */ }
        None => break,
    }
}
```

`IntoIterator` es el trait de «las cosas que se pueden convertir en un iterador»: un `Vec`, un `&Vec`, un rango `0..10`, un array… Un iterador también lo implementa (se devuelve a sí mismo). La lección siguiente explica qué sale de cada uno.

`Iterator` tiene un **tipo asociado** (`Item`, mundo 13) y no un parámetro genérico: un iterador concreto entrega un único tipo de elemento, y así el compilador siempre sabe qué sale de `next()` sin que tengas que anotarlo.

Muchos tipos de iteradores llevan el atributo `#[must_use]`: si creas uno y no lo usas, el compilador te avisa con la nota «iterators are lazy and do nothing unless consumed».

</BajoElCapo>

## Trampa típica

<Trampa titulo="Usar map para «hacer algo con cada elemento»">

`map` es para **transformar** elementos, no para provocar efectos como imprimir. Esta línea no imprime nada:

```rust
v.iter().map(|x| println!("{x}"));
```

Compilándola de verdad, el compilador da dos avisos: uno dice que la llamada a `map` descarta los valores y sugiere `for_each`; el otro, «unused `Map` that must be used», con la nota «iterators are lazy and do nothing unless consumed». En el ejemplo `m14/map-sin-consumir` subimos ese aviso a error con `#![deny(unused_must_use)]`, y la compilación falla. Para recorrer y actuar usa un `for` (o `for_each`).

</Trampa>
