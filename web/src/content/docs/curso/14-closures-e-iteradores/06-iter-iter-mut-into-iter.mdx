## La idea

Una colección como `Vec<T>` ofrece tres iteradores, uno por cada forma de acceso que ya conoces:

| Método | Atajo en un `for` | Entrega | Después, el vector… |
|---|---|---|---|
| `v.iter()` | `for x in &v` | `&T` | sigue igual y es tuyo |
| `v.iter_mut()` | `for x in &mut v` | `&mut T` | sigue siendo tuyo, quizá cambiado |
| `v.into_iter()` | `for x in v` | `T` | ya no existe: se ha movido |

La tercera forma es la que sorprende: `for x in v` **consume** el vector. Cada `String` sale del vector y pasa a ser tuya dentro del bucle. Es útil cuando ya no necesitas la colección (te ahorras clonar), pero si luego quieres usarla, recorre con `&v`.

Con tipos `Copy` (como `i32`) se nota menos, porque de un `&i32` sacas el número con `*x` o con el patrón `&x`. Con `String`, `Vec` y demás, la diferencia es la de siempre entre **prestar** y **mover**.

## Bajo el capó

<BajoElCapo>

El `for` siempre llama a `IntoIterator::into_iter(lo_que_le_des)`. Lo que cambia es **para qué tipo**: la biblioteca estándar implementa `IntoIterator` tres veces para los vectores:

```rust
impl<T> IntoIterator for Vec<T>        { type Item = T;      /* … */ }  // for x in v
impl<'a, T> IntoIterator for &'a Vec<T>     { type Item = &'a T;     /* … */ }  // for x in &v
impl<'a, T> IntoIterator for &'a mut Vec<T> { type Item = &'a mut T; /* … */ }  // for x in &mut v
```

`v.iter()` es un `std::slice::Iter<'_, T>`: un struct con dos punteros, al elemento actual y al final. Avanzar es sumar el tamaño de un `T` al primero. El tiempo de vida `'_` ata el iterador al vector: mientras el iterador exista, el vector está prestado, así que no puedes, por ejemplo, vaciarlo a mitad de recorrido. Sin esa regla, el iterador apuntaría a memoria liberada.

Los arrays también: desde la edición 2021, `[1, 2, 3].into_iter()` entrega los valores (no referencias).

</BajoElCapo>
