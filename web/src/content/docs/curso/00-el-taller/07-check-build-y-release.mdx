Hasta ahora has usado `cargo run`, que compila y ejecuta. Cargo tiene más órdenes, y elegir bien cuál usar te ahorrará mucho tiempo de espera.

## La idea

| Orden | Qué hace | Cuándo |
|---|---|---|
| `cargo check` | comprueba que todo compila; **no** genera el ejecutable | mientras escribes: es lo más rápido |
| `cargo build` | compila y genera `target\debug\hola.exe` | cuando quieres el programa sin ejecutarlo |
| `cargo run` | `build` + ejecutar | para probar |
| `cargo build --release` | compila **optimizando** → `target\release\hola.exe` | para la versión final o para medir velocidad |
| `cargo clean` | borra `target` | si algo se ha quedado raro o necesitas espacio |

Hay dos **perfiles** de compilación:

- **`dev`** (por defecto): compila deprisa y añade comprobaciones extra. Por ejemplo, si un entero se desborda, el programa se detiene con un error (mundo 03).
- **`release`** (`--release`): tarda más en compilar, pero el programa puede ser **decenas de veces más rápido**. Algunas comprobaciones se quitan.

## La carpeta target

`target\` es donde Cargo guarda todo lo que genera:

```text
target\
├── debug\           ← perfil dev
│   ├── hola.exe     ← tu programa
│   ├── deps\        ← tus dependencias compiladas
│   └── incremental\ ← datos para recompilar más rápido
└── release\         ← perfil release (si lo has usado)
```

Puede ocupar cientos de megas, pero **no es tuya**: Cargo la regenera cuando haga falta. Por eso el `.gitignore` que creó `cargo new` le dice a Git que la ignore.

Un consejo para Windows: el antivirus (Windows Defender) analiza cada archivo nuevo de `target` y eso ralentiza la compilación. Puedes añadir tu carpeta de proyectos a sus exclusiones o, mejor, crear una **Unidad de desarrollo** (*Dev Drive*), pensada justo para esto.
