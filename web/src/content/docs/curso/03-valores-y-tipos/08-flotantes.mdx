## La idea

Rust tiene dos tipos de **coma flotante** (*floating point*), los dos con el estándar IEEE 754 que viste en el Mundo 1:

- **`f64`**: 8 bytes, unas 15–17 cifras significativas. Es el tipo **por defecto**: `let x = 2.5;` es un `f64`.
- **`f32`**: 4 bytes, unas 7 cifras. Ocupa la mitad, pero es menos preciso.

Un literal con punto (`7.0`) es decimal; sin punto (`7`), entero. Y Rust **no los mezcla**: `7 / 2` es división entera (3) y `7.0 / 2.0` es decimal (3.5). Para operar un entero con un decimal tienes que convertirlo tú con `as f64`.

Los decimales tienen tres valores especiales: **infinito** (`inf`, `-inf`), que sale al dividir entre cero, y **NaN** (*Not a Number*, «no es un número»), que sale de operaciones sin sentido como 0/0. NaN tiene una propiedad extraña: **no es igual a nada, ni siquiera a sí mismo**.

## Pruébalo

<Ejecutar ej="m03/flotantes" />

Salida real:

```text
pi = 3.14159, e = 2.71828
pi con 2 decimales: 3.14
7.0 / 2.0 = 3.5
7 / 2     = 3
0.1 + 0.2 = 0.30000000000000004
es 0.3: false
f32: 0.3
```

Fíjate en la última línea: con `f32`, la misma suma **parece** exacta. No lo es: con menos bits, el error queda por debajo de lo que se imprime. `{pi:.2}` redondea **al mostrar**, no cambia el valor guardado.

Los valores especiales:

<Ejecutar ej="m03/especiales" />

```text
1.0 / 0.0 = inf
-1.0 / 0.0 = -inf
0.0 / 0.0 = NaN
nan == nan: false
nan.is_nan(): true
-0.0 == 0.0: true
casi iguales: true
```

## Bajo el capó

<BajoElCapo titulo="Lo que hay de verdad en un 0.1">
Con `{:.20}` puedes ver más decimales de los que Rust muestra por defecto, y con `to_bits()` los 64 bits tal cual:

<Ejecutar ej="m03/bits-flotante" />

Salida real:

```text
f32: 4 bytes, f64: 8 bytes
0.1 con 20 decimales: 0.10000000000000000555
bits de 0.1: 0x3fb999999999999a
f64::MAX = 1.7976931348623157e308
f64::EPSILON = 2.220446049250313e-16
```

`0x3fb999999999999a`: un bit de signo (0), 11 bits de exponente (`0x3fb`) y 52 de mantisa, `999…9a`. Ese patrón `1001 1001…` que se repite es el 0,1 en binario, que es **periódico** como 1/3 en decimal: no cabe en 52 bits y la última cifra se redondea (`…9a`). Por eso el valor guardado es 0,10000000000000000555…

`EPSILON` es la distancia entre 1.0 y el siguiente `f64` que existe: unos 2,2 × 10⁻¹⁶. Es la medida de la precisión relativa del tipo.

Que `NaN != NaN` tiene consecuencias en el diseño de Rust: los decimales **no** se pueden ordenar de forma total, así que `f64` implementa la comparación «parcial» (`PartialEq`, `PartialOrd`) pero no la total (`Eq`, `Ord`). Lo entenderás en el Mundo 13, cuando veas los traits.
</BajoElCapo>

## Trampa típica

Multiplicar unidades (entero) por precio (decimal):

<NoCompila ej="m03/mezcla" explicacion="E0277: no hay multiplicación definida entre un entero y un decimal. Rust nunca convierte en silencio; la solución es `unidades as f64 * precio`." />

El error dice «no se puede multiplicar `{integer}` por `{float}`». `{integer}` y `{float}` son la forma del compilador de decir «un entero (o decimal) cuyo tipo exacto aún no he decidido». La versión arreglada imprime `7.5`.

<Trampa titulo="Comparar decimales con ==">
❌ `if total == 0.3 { ... }`. Como has visto, `0.1 + 0.2 == 0.3` es `false`.

✅ Compara con un margen: `(total - 0.3).abs() < 1e-9`. Y para dinero exacto, usa enteros (céntimos) en lugar de decimales.
</Trampa>
