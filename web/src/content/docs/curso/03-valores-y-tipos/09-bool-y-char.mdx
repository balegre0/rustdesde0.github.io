## La idea

**`bool`** (de George Boole) tiene solo dos valores: `true` (verdadero) y `false` (falso). Es el resultado de toda comparación (`5 > 3` es `true`) y se combina con `&&` («y»), `||` («o») y `!` («no»). Ocupa 1 byte.

**`char`** es **un carácter Unicode**. Se escribe entre comillas **simples**: `'a'`, `'ñ'`, `'€'`, `'🦀'`. Por dentro es un número: el **valor escalar Unicode** (*Unicode scalar value*) de ese carácter, de 0 a 0x10FFFF. Ocupa **siempre 4 bytes**, sea una `a` o un emoji, porque 4 bytes bastan para cualquier número de ese rango.

No confundas un `char` con un texto. `'ñ'` (comillas simples) es un `char` de 4 bytes. `"ñ"` (comillas dobles) es un texto (`&str`) codificado en UTF-8, donde la ñ ocupa 2 bytes. Son tipos distintos.

## Pruébalo

<Ejecutar ej="m03/char" />

Salida real:

```text
llueve: false, sol: true
y: false, o: true
a -> U+0061, bytes en UTF-8: 1
ñ -> U+00F1, bytes en UTF-8: 2
Ω -> U+03A9, bytes en UTF-8: 2
€ -> U+20AC, bytes en UTF-8: 3
🦀 -> U+1F980, bytes en UTF-8: 4
bool ocupa 1 byte, char ocupa 4 bytes
```

`c.len_utf8()` te dice cuántos bytes **ocuparía** ese carácter dentro de un texto UTF-8: de 1 a 4. Pero como `char`, en una variable, todos miden 4.

## Bajo el capó

<BajoElCapo titulo="No todo número es un char válido">
Un `bool` ocupa un byte entero, pero solo dos patrones son válidos: `00000000` (`false`) y `00000001` (`true`). Un `char` ocupa 4 bytes, pero no todos los números de 32 bits son caracteres: solo los de 0 a 0x10FFFF, **sin** el hueco 0xD800–0xDFFF (los «sustitutos» o *surrogates*, reservados por Unicode para otra codificación). Rust **garantiza** que un `char` siempre contiene un valor válido. Por eso convertir un número en `char` puede fallar:

<Ejecutar ej="m03/char-de-numero" />

Salida real:

```text
0 1
Some('A')
Some('🦀')
None
None
char::MAX = U+10FFFF
```

`false as u8` es 0 y `true as u8` es 1. `char::from_u32` devuelve `None` para el sustituto 0xD800 y para 0x110000, que se sale del rango.

Estas garantías («un `bool` es 0 o 1», «un `char` es un valor escalar válido») son parte de las reglas de **validez** de Rust. En el código normal no puedes romperlas; en el Mundo 20 verás que, con `unsafe`, fabricar un `bool` que valga 2 es comportamiento indefinido.
</BajoElCapo>
