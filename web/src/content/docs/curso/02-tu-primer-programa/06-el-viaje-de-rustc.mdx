## La idea

`rustc` transforma tu programa en varios pasos. Cada paso produce una representación nueva, más fácil de analizar para el paso siguiente:

1. **Análisis léxico** (*lexing*): el texto se parte en **tokens**: `fn`, `main`, `(`, `)`, `{`, `"hola"`… Los comentarios normales se descartan aquí.
2. **Análisis sintáctico** (*parsing*): los tokens se organizan en un árbol, el **AST** (*abstract syntax tree*, árbol de sintaxis abstracta). Un paréntesis sin cerrar falla en este punto.
3. **Expansión de macros y resolución de nombres**: `println!` se sustituye por su código, y cada nombre (`x`, `nombre`, `println`) se enlaza con lo que significa. Aquí nace E0425, «cannot find value».
4. **HIR** (*high-level IR*, representación intermedia de alto nivel): el AST «desazucarado», con algunas construcciones cómodas ya traducidas a otras más simples.
5. **Comprobación de tipos** (*type checking*): se deduce el tipo de cada valor y se comprueba que todo encaja. Aquí nace E0308, «mismatched types».
6. **MIR** (*mid-level IR*): el programa como un grafo de **bloques básicos** con instrucciones muy simples. Sobre el MIR trabaja el **borrow checker**, el comprobador de préstamos que protagonizará los mundos 6 a 8.
7. **Generación de código** (*codegen*): el MIR se traduce a **LLVM IR**, y LLVM (un proyecto de compilador independiente) lo optimiza y lo convierte en código máquina.
8. **Enlazado** (*linking*): el **enlazador** (*linker*) junta tu código con el de la biblioteca estándar en un ejecutable. En Windows con MSVC, ese enlazador es `link.exe`.

## Pruébalo

Un programa diminuto:

<Ejecutar ej="m02/minimo" />

```text
5
```

Ahora vas a mirar una de las paradas intermedias. `rustc --emit=mir` escribe el MIR en un archivo en vez de generar el programa. Este es un fragmento real del MIR de `main` (Rust 1.99.1, compilado en modo depuración):

```text
    bb0: {
        _5 = AddWithOverflow(const 2_i32, const 3_i32);
        assert(!move (_5.1: bool), "attempt to compute `{} + {}`, which would overflow", const 2_i32, const 3_i32) -> [success: bb1, unwind unreachable];
    }
```

`bb0` es el **bloque básico** 0. `_5` es una variable interna que guarda dos cosas: el resultado de `2 + 3` y un indicador de si la suma se ha salido de rango. La instrucción `assert` comprueba ese indicador: si la suma desbordara, el programa se detendría con el mensaje «attempt to compute … which would overflow». Esa comprobación existe porque se compiló en modo depuración. Con `-O` (optimizado, como `cargo build --release`), el mismo MIR trae una suma simple, `Add(const 2_i32, const 3_i32)`, sin comprobación. Esta diferencia entre los dos modos la estudiarás en el mundo 3.

Más abajo, en el mismo MIR, aparece `std::io::_print(move _2)`: la expansión de `println!` que viste en la lección de las macros.

## Bajo el capó

<BajoElCapo titulo="Las piezas del compilador y lo que hace cargo check">
El propio `rustc` está escrito en Rust y dividido en muchos crates. Según la guía para desarrolladores del compilador (*rustc-dev-guide*), algunas de las piezas son: `rustc_lexer` (tokens), `rustc_parse` y `rustc_ast` (el AST), `rustc_expand` (macros), `rustc_hir` (el HIR), `rustc_mir_build` y `rustc_mir_transform` (construir y transformar el MIR), `rustc_borrowck` (el borrow checker) y `rustc_codegen_ssa` con `rustc_codegen_llvm` (la generación de código).

**`cargo check`** recorre las fases hasta el borrow checker y se detiene: guarda solo los **metadatos** (`--emit=metadata`) y no genera código máquina. Por eso es mucho más rápido que `cargo build`, y por eso funciona aunque falte `link.exe`: el enlazador es la **última** parada, y `cargo check` no llega hasta ella. Es la herramienta que este curso usa para comprobar que un ejemplo compila en una máquina sin enlazador.

**El tamaño.** El programa de esta lección, compilado para el navegador con optimización de tamaño y sin símbolos, ocupa unos 47 KB. Casi todo es la parte de la biblioteca estándar que hace falta para imprimir; tu `main` son unas pocas instrucciones.

Las representaciones internas (MIR, LLVM IR) **cambian entre versiones** del compilador. No memorices su texto: aprende a pedirlas y a reconocer las ideas.
</BajoElCapo>
