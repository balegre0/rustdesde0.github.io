## La idea

Un programa de Rust está hecho de **funciones** (*functions*): trozos de código con nombre que hacen una tarea. Mira el programa mínimo pieza a pieza:

```rust
fn main() {
    println!("¡Hola, mundo!");
}
```

- `fn` es una **palabra clave** (*keyword*): le dice al compilador «aquí empieza una función».
- `main` es el **nombre** de la función. No es un nombre cualquiera: es el **punto de entrada** (*entry point*). Cuando ejecutas el programa, lo primero tuyo que corre es `main`.
- `()` son los **parámetros**: los datos que recibe la función. `main` no recibe ninguno, así que los paréntesis van vacíos (pero son obligatorios).
- `{ … }` es el **cuerpo**: las instrucciones que se ejecutan. Cada instrucción de este tipo termina en `;`.

Dentro del cuerpo, las instrucciones se ejecutan **en orden, de arriba abajo**, una sola vez cada una. Más adelante aprenderás a cambiar ese orden (repetir, saltarte trozos), pero la regla por defecto es esa. Los espacios del principio de la línea (la **sangría**, *indentation*) no cambian nada para el compilador: sirven para que tú veas qué está dentro de qué. La forma estándar la pone `cargo fmt` por ti.

## Bajo el capó

<BajoElCapo titulo="¿De verdad main es lo primero que se ejecuta?">
Lo primero *tuyo*, sí. Pero antes de `main` corre un poco de código de la **biblioteca estándar** (*standard library*, `std`) que prepara el terreno: deja listos los argumentos del programa y la salida de texto, y luego llama a tu `main`. Cuando `main` termina, ese mismo código convierte el final en un **código de salida** para el sistema operativo: `0` significa «todo bien».

Puedes verlo pidiendo al compilador su representación intermedia para LLVM (`rustc --emit=llvm-ir`). En la de este programa aparece una función de `std` llamada `std::rt::lang_start` (*rt* = *runtime*, «entorno de ejecución») que recibe tu `main` como argumento, y otra llamada `Termination::report`, que traduce el final de `main` en ese código de salida. Tu `main` aparece como una función más, `hola::main`.

Por eso, si borras `main`, el compilador no tiene a quién pasarle a `lang_start` y se niega a construir el ejecutable.
</BajoElCapo>

## Trampa típica

Llamar a la función de otra forma, aunque sea en español, no sirve: el punto de entrada **tiene** que llamarse `main`.

<NoCompila ej="m02/sin-main" explicacion="El error E0601 dice que no hay función `main` en el crate. Rust no adivina cuál de tus funciones es la principal: la busca por su nombre." />

El mensaje real empieza así: «`main` function not found in crate `sin_main`» (no se encontró la función `main` en el crate). Un **crate** es la unidad que compila `rustc` de una vez: aquí, tu archivo. Pulsa «Ver arreglo» para ver la versión que funciona.
