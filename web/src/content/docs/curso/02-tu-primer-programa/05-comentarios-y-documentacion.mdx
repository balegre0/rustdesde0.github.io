## La idea

Un **comentario** (*comment*) es texto para personas que el compilador descarta. Hay dos formas:

- `//` hasta el final de la línea. Es la forma normal en Rust; también sirve para «apagar» una línea de código sin borrarla.
- `/* … */` puede ocupar varias líneas. En Rust estos bloques **se anidan**: `/* fuera /* dentro */ todavía fuera */` es un solo comentario.

Además existen los **comentarios de documentación** (*doc comments*), que no se descartan: se guardan y sirven para generar la documentación.

- `///` documenta lo que viene **justo debajo** (una función, por ejemplo).
- `//!` documenta lo que lo **contiene**. Al principio de `main.rs`, documenta el programa entero.

Dentro de ellos se escribe en **Markdown**: `# Título`, `` `código` ``, listas… Es el mismo formato con el que está escrita la documentación oficial de Rust.

Ahora un programa documentado. `fn saludar(nombre: &str)` es una función que recibe un texto; las funciones con parámetros llegan en el mundo 5, de momento fíjate en los comentarios:

<Ejecutar ej="m02/documentado" />

```text
¡Hola, Ana!
¡Hola, Luis!
```

Si copias este programa en `src/main.rs` de un proyecto llamado `saludos` y ejecutas `cargo doc --no-deps`, Cargo genera la web de documentación. Salida real (la ruta está abreviada):

```text
 Documenting saludos v0.1.0 (…\saludos)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.23s
   Generated …\saludos\target\doc\saludos\index.html
```

La portada muestra el texto del `//!` («Un programa diminuto para practicar la documentación») y hay una página `fn.saludar.html` con el texto del `///`. Con `cargo doc --open` se abre directamente en el navegador. `cargo doc` no necesita el enlazador, así que funciona aunque todavía no hayas resuelto la trampa de `link.exe`.

## Bajo el capó

<BajoElCapo titulo="Qué hace el compilador con cada comentario">
El primer paso de `rustc` es partir tu texto en **tokens** (palabras sueltas como `fn`, `main`, `(`, `"hola"`). En ese paso, los comentarios normales **desaparecen**: no llegan a ninguna fase posterior y no ocupan ni un byte del programa final.

Los comentarios de documentación, en cambio, se convierten en un **atributo** (*attribute*): `/// Hola` es otra forma de escribir `#[doc = " Hola"]` (fíjate en el espacio inicial, que se conserva). Puedes comprobarlo: si escribes `#[doc = "Documentada con el atributo."]` encima de una función, `cargo doc` muestra ese texto igual que si hubieras usado `///`.

Como un atributo tiene que estar pegado a algo, un `///` que no tiene nada debajo es un error, y no un simple comentario ignorado. Lo vas a ver ahora.
</BajoElCapo>

<NoCompila ej="m02/doc-suelto" explicacion="E0585: el `///` está al final de `main`, sin nada debajo que documentar. El `help:` lo explica: los comentarios de documentación van antes de lo que documentan; si querías un comentario normal, usa `//`." />
