## La idea

Un error de `rustc` siempre tiene la misma forma. Míralo en el error de arriba, línea a línea:

1. **Cabecera**: ``error[E0384]: cannot assign twice to immutable variable `puntos` ``. El **nivel** (`error`), el **código** (`E0384`) y un resumen en una frase («no se puede asignar dos veces a la variable inmutable `puntos`»).
2. **Ubicación**: `--> …/asignar-inmutable.rs:4:5`. Archivo, línea 4, columna 5.
3. **El código, con marcas**. A la izquierda, un margen con los números de línea y una barra `|`. Debajo de cada línea, marcas: `^^^` es el **sitio principal** («cannot assign twice to immutable variable»), y `---` un **sitio relacionado** («first assignment to `puntos`», la primera asignación).
4. **`help:`**: una propuesta de arreglo, muchas veces con el código ya corregido. Aquí: «consider making this binding mutable» (plantéate hacer mutable esta variable), con `+++` debajo del `mut` que falta.
5. **`note:`** (si hay): información extra, como por qué una regla existe o qué opción la activa.
6. **El final**: `error: aborting due to 1 previous error` (se aborta por 1 error) y ``For more information about this error, try `rustc --explain E0384`.``

Esa última línea es una invitación: cada código `E` tiene una **ficha** con una explicación larga y ejemplos. Está dentro del propio compilador, así que funciona sin conexión.

## Pruébalo

Ejecuta en tu terminal `rustc --explain E0384`. Empieza así (salida real, en inglés):

```text
An immutable variable was reassigned.

Erroneous code example:
```

«Se ha reasignado una variable inmutable», seguido de un ejemplo erróneo y de cómo arreglarlo con `mut`. Ahora, dos errores más que verás a menudo. Primero, un tipo equivocado:

La marca `---` bajo `i32` explica el porqué: «expected due to this», se esperaba por esto." />

Y un nombre mal escrito:

<NoCompila ej="m02/nombre-desconocido" explicacion="E0425, «cannot find value `nombe` in this scope» (no se encuentra el valor `nombe` aquí). El `help:` encuentra la variable parecida, «a local variable with a similar name exists», y marca con `+` la letra que falta." />

Lee los tres con calma: código, frase, ubicación, marcas, `help:`. En los tres, el `help:` traía el arreglo exacto.

## Bajo el capó

<BajoElCapo titulo="El mismo error, para máquinas">
Lo que ves en la terminal es una versión para personas. Con `rustc --error-format=json` el compilador emite el mismo error como datos estructurados, que es lo que leen los editores (rust-analyzer) y lo que usa este curso para mostrarte los errores reales en cada lección. Para el error E0308 de arriba, el JSON real incluye, entre otros, estos campos:

- `"level": "error"` y `"code": {"code": "E0308", "explanation": "Expected type did not match the received type. …"}`: el código y **la ficha entera** de `--explain`.
- `"message": "mismatched types"`.
- `"spans"`: los trozos de código marcados, con `"line_start": 2`, `"column_start": 21` y la etiqueta ``"expected `i32`, found `&str`"``.
- `"rendered"`: el texto ya dibujado, tal como sale en la terminal.

Cada `^^^` o `---` de la terminal es un **span** (un tramo de código, de una columna a otra) con su etiqueta. Por eso tu editor puede subrayarte el sitio exacto.

Y una advertencia honesta, que viene de la investigación sobre cómo aprende la gente Rust: los mensajes son muy buenos, pero **no siempre cuentan toda la historia**. En un estudio con 110 errores reales, en 51 el mensaje se quedaba corto para entender la causa. Ya lo viste en la lección de formato, con `{edad + 1}`: el compilador hablaba de una opción `+` mal colocada. Lee el mensaje, pero piensa también tú.
</BajoElCapo>

## Trampa típica

<Trampa titulo="Aplicar el help: sin pensar">
❌ Copiar el arreglo del `help:` en cuanto aparece. Suele acertar, pero el compilador solo ve el código, no tu intención. En el ejemplo de E0384, añadir `mut` es correcto **si** querías que los puntos cambiaran. Si no, el error de verdad es la línea 4, que no debería existir.

✅ Antes de aplicar el `help:`, pregúntate: «¿qué quería hacer yo?». Si el arreglo coincide con tu intención, adelante. Si no, el error te está señalando un fallo de diseño, no de escritura.
</Trampa>
