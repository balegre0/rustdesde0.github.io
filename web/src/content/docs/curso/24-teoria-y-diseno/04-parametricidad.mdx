*Polimorfismo* significa «muchas formas»: un mismo código que funciona con muchos tipos. Hay tres maneras de conseguirlo, y Rust usa las tres de forma muy distinta.

## La idea

| Clase | Qué es | En Rust |
|---|---|---|
| **Paramétrico** | el mismo código para todos los tipos, sin mirar cuál es | genéricos: `fn invertir<T>(v: Vec<T>)` |
| **Ad hoc** | un comportamiento distinto para cada tipo, bajo un mismo nombre | traits: `impl Display for Punto` |
| **De subtipos** | un valor de un tipo «más específico» sirve donde se pide uno «más general» | solo entre lifetimes: `&'static str` donde se pide `&'a str` |

Rust **no** tiene subtipos entre structs (no hay herencia). Su único subtipado es el de las lifetimes, con la varianza del mundo 08.

**Parametricidad.** Una función genérica **sin cotas** no sabe nada de `T`: no puede crear un `T`, ni compararlo, ni imprimirlo. Eso limita tanto lo que puede hacer que **la firma casi dice el comportamiento**:

- `fn f<T>(x: T) -> T` solo puede ser la identidad (o no terminar).
- `fn f<T>(a: T, b: T) -> T` solo puede devolver `a` o `b`.
- `fn f<T>(v: Vec<T>) -> Vec<T>` solo puede reordenar, repetir o quitar elementos, **sin mirarlos**. Por eso, para cualquier función `g`, da igual aplicar `g` antes o después.

A estos resultados se les llama, con humor, **teoremas gratis** (*theorems for free*, Wadler 1989): se deducen de la firma, sin leer el cuerpo.

## Bajo el capó

<BajoElCapo>

**Las cotas abren puertas.** `fn f<T: Debug>(x: T)` ya puede imprimir `x`; `T: Default` puede crear un `T`; `T: Ord` puede ordenarlos. Cada cota es una capacidad que pides y que el que llama tiene que proporcionar. Cuanto menos pidas, más cosas aceptas y más garantías da tu firma.

**Fugas de la parametricidad en Rust.** Hay formas de «mirar» `T` sin cota: `size_of::<T>()` da su tamaño y `std::any::type_name::<T>()` su nombre; con `T: 'static`, `TypeId::of::<T>()` y `Any` permiten preguntar el tipo al ejecutar. Y la **especialización** (inestable) permitiría implementar un trait de forma distinta para un tipo concreto. Por eso la parametricidad en Rust es casi total, pero no absoluta.

**Monomorfización.** El polimorfismo paramétrico de Rust se compila generando una copia del código para cada tipo usado (mundo 21). La teoría no cambia: todas las copias hacen lo mismo, porque el código no puede mirar `T`.

</BajoElCapo>
