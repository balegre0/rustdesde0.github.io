En el mundo 07 viste **cómo** se usa un préstamo. Aquí verás **cuánto** puede durar. La regla nueva cabe en una frase:

> **Una referencia nunca puede vivir más que el valor al que apunta.**

Si pudiera, apuntaría a memoria ya liberada: una **referencia colgante** (*dangling reference*), el error de memoria más clásico. Para impedirlo, el compilador le asigna a cada referencia una **lifetime** (literalmente, «tiempo de vida»): el tramo del programa durante el que tiene que ser válida.

Casi siempre el compilador calcula las lifetimes solo. Solo tienes que escribirlas (con la sintaxis `'a`) cuando una función o un struct **relaciona** varias referencias y el compilador no puede adivinar cómo. Este es el tema que más cuesta en Rust: según un estudio con estudiantes, confunde a más del 85 % al principio. Por eso va despacio, con un único concepto por lección.

:::note[Una palabra sobre el vocabulario]
En español no hay una traducción asentada de *lifetime*, así que el curso usa la palabra inglesa, como la documentación oficial y la comunidad. Cuando ayude a entender, la llamaremos también **región**: un conjunto de puntos del programa.
:::

## Lo que el compilador vigila en este mundo

| Error | Qué te impide hacer | Qué fallo de memoria evita |
|---|---|---|
| [E0597](/errores/e0597/) | Que una referencia se use después de que su valor termine | Referencia colgante (uso tras liberar) |
| [E0515](/errores/e0515/) | Devolver una referencia a una variable local | Apuntar a un marco de pila que ya no existe |
| [E0106](/errores/e0106/) | Devolver una referencia sin decir de qué entrada sale | Que el que llama no sepa cuánto puede usarla |
| [E0716](/errores/e0716/) | Usar una referencia a un temporal que ya se destruyó | Referencia colgante a un valor sin nombre |
| [E0310](/errores/e0310/) | Guardar como `'static` un tipo que podría llevar referencias cortas | Que algo guardado «para siempre» apunte a memoria liberada |
