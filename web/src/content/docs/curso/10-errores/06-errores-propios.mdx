## La idea

Un error con forma de `String` sirve para mostrarlo, pero no para **decidir** nada: quien llama solo puede leer texto. Un **enum de error** tiene un caso por cada forma de fallar, con los datos que hacen falta para entenderlo:

```rust
enum ErrorClave {
    Corta { largo: usize, minimo: usize },
    SinNumero,
    Prohibida(String),
}
```

Para que se comporte como un error «de verdad», le das tres cosas:

1. **`Debug`** (con `#[derive(Debug)]`): la vista para programadores.
2. **`Display`** (escrito a mano): el mensaje para personas. Se implementa con un método `fmt` que escribe con `write!(f, "…")`.
3. **`std::error::Error`**: el trait que dice «esto es un error». Exige `Debug` + `Display` y no necesita nada más: `impl std::error::Error for ErrorClave {}`.

Los traits (un `impl Algo for Tipo` que da a un tipo ciertas capacidades) se estudian a fondo en el mundo 13. Aquí basta con copiar la forma.

## Bajo el capó

<BajoElCapo>

`Display` y `Debug` son traits de formato. `println!("{}", e)` termina llamando a `Display::fmt(&e, f)`, donde `f` es un `Formatter`: un objeto que sabe dónde escribir (la consola, un `String`…) y con qué opciones (ancho, alineación). `write!(f, …)` escribe en él y devuelve `fmt::Result` (que es `Result<(), fmt::Error>`), así un fallo de escritura se propaga hacia arriba.

El trait `Error` vive en `core` (desde Rust 1.81), así que también existe en programas sin sistema operativo. Sus métodos tienen implementación por defecto; el más útil es `source()`, que dice qué otro error causó este (lección 8). En memoria, tu enum de error es un enum normal: si es pequeño, devolver `Result<T, ErrorClave>` es barato.

</BajoElCapo>
