## La idea

Muchas funciones hacen varias cosas que pueden fallar, y ante cualquier fallo quieren lo mismo: **dejar de trabajar y pasar el error a quien las llamó**. Escrito con `match`, cada paso son cuatro líneas:

```rust
let n = match texto.parse::<i32>() {
    Ok(valor) => valor,
    Err(e) => return Err(e),
};
```

El operador **`?`** (*question mark operator*) escribe eso por ti: `let n: i32 = texto.parse()?;`. Si el resultado es `Ok`, te da el valor; si es `Err`, **sale de la función** devolviendo ese error. Funciona igual con `Option`: `None` sale de la función con `None`.

Una condición: la función que contiene el `?` tiene que devolver un tipo donde quepa ese error. `?` sobre un `Result` exige que la función devuelva un `Result`; sobre un `Option`, un `Option`. No se mezclan solos (se convierten con `.ok()` o `.ok_or(…)`, lección 5).

## Bajo el capó

<BajoElCapo>

La expansión exacta de `expr?` para `Result` es casi la de arriba, con un detalle importante:

```rust
match expr {
    Ok(v) => v,
    Err(e) => return Err(From::from(e)),
}
```

Ese `From::from(e)` **convierte** el error al tipo de error de tu función. Si son el mismo tipo, no hace nada; si no, busca una conversión. Es lo que permite que una función que devuelve `Result<_, MiError>` use `?` sobre errores de tipos distintos (lección 7).

Oficialmente, `?` funciona con cualquier tipo que implemente el trait `Try` (todavía inestable); en Rust estable, en la práctica, `Result`, `Option` y algunos tipos de la biblioteca como `ControlFlow` y `Poll`. El compilador lo traduce a `match` antes de generar código: un `?` cuesta lo mismo que el `match` que escribirías a mano, ni más ni menos. Existe desde Rust 1.13 (2016); antes se usaba una macro llamada `try!`.

</BajoElCapo>
