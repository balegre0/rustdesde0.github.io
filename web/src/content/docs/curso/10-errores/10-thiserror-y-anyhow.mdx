## La idea

Escribir `Display`, `Error`, `source` y un `From` por cada causa (lecciones 6–8) es siempre igual. Dos bibliotecas muy usadas, ambas de David Tolnay, lo automatizan:

- **thiserror**, para **bibliotecas**: describes el enum con atributos y genera el código repetitivo. El resultado es un enum normal y concreto, exactamente como el que escribirías a mano.
- **anyhow**, para **aplicaciones**: un tipo `anyhow::Error` que admite cualquier error (como `Box<dyn Error>`, mejorado) y el método `.context("…")` para añadir qué estabas haciendo cuando falló.

En el navegador **no hay bibliotecas externas**, solo la estándar. Así que primero lo escribimos a mano (eso sí se ejecuta), y después ves el aspecto que tendría con cada biblioteca.

## Pruébalo

Lo que generaría thiserror, escrito a mano:

<Ejecutar ej="m10/a-mano-como-thiserror" />

Con thiserror, el mismo error se escribiría así.

```rust
// CONCEPTO — no ejecutable aquí: necesita el crate thiserror (Cargo.toml: thiserror = "2")
use thiserror::Error;

#[derive(Debug, Error)]
enum ErrorDescarga {
    #[error("la URL «{0}» no es válida")]
    UrlInvalida(String),
    #[error("puerto inválido")]
    Puerto(#[from] std::num::ParseIntError),
}
```

Y la idea de anyhow (añadir contexto y encadenar la causa), escrita a mano:

<Ejecutar ej="m10/a-mano-como-anyhow" />

```rust
// CONCEPTO — no ejecutable aquí: necesita el crate anyhow (Cargo.toml: anyhow = "1")
use anyhow::{Context, Result};

fn leer_ancho(texto: &str) -> Result<u32> {
    let n = texto.parse::<u32>().context("leyendo el ancho de la ventana")?;
    Ok(n)
}
```

La idea es la misma que en nuestro ejemplo escrito a mano: el texto de `context` es el mensaje, y el error original queda como causa.

## Bajo el capó

<BajoElCapo>

`#[derive(Error)]` es una **macro procedural** (mundo 19): un programa en Rust que el compilador ejecuta *durante la compilación* y que lee tu enum y escribe el `impl Display`, el `impl Error` (con `source`) y los `impl From`. No añade nada al ejecutar: el resultado es idéntico a tu versión a mano.

`anyhow::Error` guarda, como `Box<dyn Error>`, un error de cualquier tipo en el heap, y añade el contexto. Comparte su límite: quien recibe el error no puede hacer `match` sobre él.

Por qué no lo hemos podido ejecutar ni comprobar en esta máquina: los dos crates necesitan compilar y **enlazar** pequeños programas auxiliares (sus *build scripts* y la macro procedural), y aquí falta el enlazador `link.exe`. `cargo check` se detuvo con `error: linking with link.exe failed: exit code: 1` y `error: could not compile thiserror (build script) due to 1 previous error`. Es la trampa de instalación del mundo 0: con las Build Tools de Visual Studio (o la toolchain `gnullvm`) funcionan.

</BajoElCapo>

## Trampa típica

<Trampa titulo="anyhow en una biblioteca">

❌ Si tu biblioteca devuelve `anyhow::Result`, obligas a todos tus usuarios a depender de anyhow y les quitas la posibilidad de distinguir errores.

✅ La regla del ecosistema: **bibliotecas → enums concretos (thiserror o a mano); aplicaciones → anyhow (o `Box<dyn Error>`)**. Una aplicación puede usar anyhow y aun así recibir los enums concretos de sus bibliotecas: el `?` los convierte.

</Trampa>
