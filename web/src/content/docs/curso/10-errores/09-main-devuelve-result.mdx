## La idea

`main` puede devolver `Result<(), E>`, con cualquier `E` que implemente `Debug`. Así puedes usar `?` en `main` igual que en cualquier otra función:

- si `main` devuelve `Ok(())`, el programa termina bien (código de salida **0**);
- si devuelve `Err(e)`, Rust escribe `Error: ` y el error **con formato Debug** en la salida de errores (*stderr*), y el programa termina con código **1**.

El **código de salida** es un número que el programa entrega al sistema operativo al terminar: 0 significa «todo bien» y cualquier otro, «algo falló». Lo usan los scripts y otras herramientas para saber si tu programa funcionó.

La firma favorita para programas pequeños es `fn main() -> Result<(), Box<dyn Error>>`: con ella, `?` acepta cualquier error.

## Bajo el capó

<BajoElCapo>

Tu `main` no es lo primero que se ejecuta: la biblioteca estándar tiene un pequeño arranque que prepara el entorno, llama a tu `main` y, con lo que devuelve, decide el código de salida. Para eso usa el trait `Termination`, que implementan `()`, `ExitCode`, `Result<(), E>` (con `E: Debug`) y algunos más. La implementación para `Result` es la que imprime `Error: {:?}` y devuelve el código 1. Lo has visto en el ejemplo: el arranque mostró `Error: SinPermiso { usuario: "marta" }` y el programa terminó con código 1.

Que use **Debug** y no Display es una decisión de diseño: Debug existe casi siempre (se deriva) y muestra más detalle. Pero para un usuario final suele ser feo. Si quieres controlar el mensaje y el código, haz que `main` devuelva `ExitCode` y trata el error tú:
