Los préstamos brillan con las colecciones: recorrer un `Vec`, modificar sus elementos, leer uno sin sacarlo. Aquí vas a ver las tres formas de recorrer y los dos errores que más aparecen con colecciones.

## Predice

<NoCompila ej="m07/p-mutar-mientras-recorre" explicacion={"Piensa antes de leer: mientras el `for` va por el elemento 2, el `push` añade otro. ¿Qué podría pasarle al recorrido si el vector se mudara a otro bloque de memoria?"} />

## La idea

**Tres formas de recorrer**, tres préstamos distintos:

| Escribes | Cada `x` es | El vector, después |
|---|---|---|
| `for x in &v` | `&T`: lees cada elemento | intacto |
| `for x in &mut v` | `&mut T`: modificas cada elemento | modificado |
| `for x in v` | `T`: te quedas con cada elemento | **movido**: ya no existe |

**No se modifica lo que se está recorriendo.** `for x in &v` mantiene un préstamo compartido de `v` **durante todo el bucle**. Un `push` dentro pide uno exclusivo: E0502. Y es una suerte, porque si `push` reubicara el vector, el recorrido seguiría avanzando por memoria liberada. Este fallo tiene nombre: **invalidación de iteradores** (*iterator invalidation*).

**No se saca nada de un préstamo.** Si solo tienes `&v`, puedes mirar los elementos pero no **llevártelos**: eso sería mover algo que no es tuyo. Es el E0507.

## Bajo el capó

<BajoElCapo>

**`for x in &v` es azúcar.** El compilador lo convierte en `(&v).into_iter()`, que da un iterador de `&T`. Ese iterador guarda dentro una referencia al vector (en realidad, dos punteros: el elemento actual y el final). Mientras el iterador vive (todo el bucle), el préstamo vive. Lo verás a fondo en el mundo 14.

**Por qué E0507 aunque el índice sea válido.** No es un problema de índices: es de propiedad. Para un tipo `Copy` como `i32`, `let n = v[0];` funciona porque **copia**. Para un `String`, «sacarlo» deja el hueco con unos bytes que el vector seguiría considerando suyos.

**Las formas legales de sacar algo** (cuando tienes `&mut`):

- `v.remove(i)` o `v.pop()`: el vector deja de tener ese elemento y te lo da.
- `std::mem::take(&mut v[i])`: te llevas el valor y deja en su sitio el valor por defecto (un `String` vacío).
- `std::mem::replace(&mut v[i], otro)` y `std::mem::swap`: cambias uno por otro.

En todas, el vector **nunca** queda con un hueco.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Arreglar E0507 con clone() sin pensar">

El compilador sugiere a menudo `help: consider cloning the value`. Clonar funciona, pero **duplica** el texto en el heap.

❌ `v[0].clone()` en un bucle de un millón de vueltas solo para imprimir.

✅ Pregúntate si necesitas **tu propia copia** o te basta con **mirar**. Para mirar, `&v[0]`. Para quedártelo de verdad y que el vector lo pierda, `remove` o `take`. Clona solo cuando de verdad quieres dos copias independientes.

</Trampa>
