## La idea

Muchas operaciones pueden no tener respuesta: buscar un nombre que no está, pedir el primer elemento de una lista vacía, leer un campo opcional. En Rust **no existe un valor «nulo»** escondido dentro de cualquier tipo. Si algo puede faltar, su tipo lo dice:

```rust
enum Option<T> {
    Some(T),   // hay un valor de tipo T
    None,      // no hay nada
}
```

Es un enum normal (de la lección anterior), con un parámetro `T` que significa «cualquier tipo» (los genéricos llegan en el mundo 13). Un `i32` **siempre** es un número. Un `Option<i32>` puede ser un número o nada, y el compilador **no te deja usarlo como número** hasta que trates el caso `None`. El olvido («daba por hecho que estaba») deja de ser un fallo al ejecutar y pasa a ser un error de compilación.

Escalera para sacar el valor, de más explícito a más cómodo: `match` → `if let` (lección 9) → métodos como `unwrap_or`, `map`, `is_some` → el operador `?` (mundo 10).

## Bajo el capó

<BajoElCapo>

¿Cuesta memoria esta seguridad? A veces nada. En wasm32, un `&i32` ocupa 4 bytes y un `Option<&i32>` **también 4**: una referencia nunca puede valer 0, así que el compilador usa la dirección 0 para representar `None`. Ese valor «imposible» que sobra se llama **nicho** (*niche*). En cambio, un `Option<u32>` ocupa 8, porque un `u32` puede valer cualquier cosa y hace falta una etiqueta aparte. Lo medirás tú mismo en la lección 10.

Así, `Option<&T>` tiene en memoria **exactamente la misma forma** que un puntero que puede ser nulo, pero con una diferencia: el tipo te obliga a comprobarlo antes de usarlo. Leer a través de una referencia nula es **comportamiento indefinido**; en Rust seguro no se puede ni escribir.

</BajoElCapo>

El mensaje real es `called Option::unwrap() on a None value`, con la línea exacta. Úsalo solo cuando un `None` sea imposible por cómo está escrito el programa; si no, trata el caso.
