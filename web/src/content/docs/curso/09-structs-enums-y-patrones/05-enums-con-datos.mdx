## La idea

Un struct dice «**y**»: un libro tiene título *y* páginas *y* … Un **enum** (*enumeration*) dice «**o**»: un mensaje es `Salir` *o* `Mover` *o* `Escribir`. Cada caso se llama **variante** (*variant*), y cada variante puede llevar **sus propios datos**:

```rust
enum Mensaje {
    Salir,                      // sin datos
    Mover { x: i32, y: i32 },   // campos con nombre
    Escribir(String),           // datos por posición
}
```

La gran ventaja: **no hay combinaciones absurdas**. Un `Mensaje::Salir` no tiene `x` ni `texto` «vacíos» que alguien pueda leer por error; simplemente no los tiene. Y para llegar a los datos tienes que preguntar antes qué variante es, normalmente con `match`. El compilador se encarga de que no te olvides de ninguna (lo verás a fondo en la lección 7).

## Bajo el capó

<BajoElCapo>

Un enum con datos se guarda como una **etiqueta** (*tag* o *discriminante*: un número que dice qué variante es) más **espacio para la variante más grande**. Todas las variantes comparten ese espacio; solo una lo usa cada vez.

```text
Forma (24 bytes en wasm32):
   [etiqueta][relleno][ espacio de datos: 16 bytes             ]
Circulo:    0          radio (8)        ··· sin usar ···
Rectangulo: 1          ancho (8)        alto (8)
Punto:      2          ··· sin usar ···
```

Por eso `Forma` ocupa lo que su variante más grande (`Rectangulo`, 16 bytes) más la etiqueta, redondeado al alineamiento de `f64` (8): **24 bytes** en wasm32 (medido con `size_of` en la lección 10). Un `Punto` ocupa lo mismo que un `Rectangulo`: es el precio de poder guardarlos juntos en un `Vec<Forma>`. El `match` lee la etiqueta y salta al brazo correcto.

</BajoElCapo>
