## La idea

Un patrón es una **plantilla con huecos**. Las partes fijas se comparan (`0`, `'ñ'`, `Forma::Punto`); los nombres son huecos que se rellenan con lo que haya en esa posición. Las piezas que puedes combinar:

| Pieza | Ejemplo | Encaja con… |
|---|---|---|
| literal | `0`, `'a'`, `true` | ese valor exacto |
| nombre | `x` | cualquier cosa, y la guarda en `x` |
| comodín | `_` | cualquier cosa, sin guardarla |
| rango | `1..=9`, `'a'..='z'`, `65..` | valores dentro del rango |
| alternativa | `'ñ' \| 'Ñ'` | cualquiera de las opciones |
| enlace | `n @ 1..=9` | lo de la derecha, y lo guarda en `n` |
| tupla, struct, variante | `(a, 0)`, `Punto { x, .. }`, `Some(v)` | esa forma, desmontada |
| slice | `[primero, .., ultimo]`, `[c, resto @ ..]` | listas con esa forma |
| guarda | `p if p > 10` | el patrón, si además se cumple la condición |

Lo potente es que **se anidan**: `Evento::Clic { pos: Punto { x: 0, y: 0 }, .. }` encaja con «un clic cuya posición es exactamente el origen, sea cual sea el resto». Todo se comprueba en una sola línea y el compilador sigue verificando que el `match` sea exhaustivo.

## Bajo el capó

<BajoElCapo>

Cuando desmontas algo **prestado** (`match e` con `e: &Evento`), los nombres del patrón no se llevan los datos: se convierten en **préstamos** de cada campo. Por eso, en el ejemplo, `boton` es un `&u8` y en la guarda escribimos `*boton == 2`. Esto se llama **modo de enlace por defecto** (*default binding mode*, apodado *match ergonomics*): al atravesar una referencia, el patrón pasa a enlazar con `ref` automáticamente.

Si en cambio desmontas **por valor** (`match e` con `e: Evento`), los campos que no son `Copy` se **mueven** a las variables del patrón, y el valor original queda movido (total o parcialmente). Las reglas de propiedad no tienen excepciones dentro de un patrón.

</BajoElCapo>
