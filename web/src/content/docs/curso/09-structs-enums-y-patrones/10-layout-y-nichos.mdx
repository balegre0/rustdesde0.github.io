## La idea

Ya sabes que un enum guarda una **etiqueta** y el espacio de su variante más grande. Pero a veces la etiqueta **no ocupa nada**. El truco: muchos tipos tienen **valores imposibles**.

- Una referencia `&T` o un `Box<T>` **nunca** valen 0 (siempre apuntan a algo).
- Un `bool` solo puede ser 0 o 1: los valores 2 a 255 de su byte están libres.
- Un `char` solo llega hasta `0x10FFFF`: sobran millones de valores.

Un valor imposible se llama **nicho** (*niche*). El compilador lo aprovecha para codificar las variantes sin datos: en `Option<&T>`, el 0 significa `None`. Resultado: `Option<&T>` ocupa **lo mismo que `&T`**. Pero solo hay **un** 0 por puntero: si el enum necesita dos casos sin datos (`TresCasos` abajo), ya no basta y vuelve la etiqueta.

## Pruébalo

<Ejecutar ej="m09/nichos" />

Los números son de **wasm32** (el navegador), donde un puntero mide 4 bytes. En un PC x86-64 los que llevan punteros se duplican: `&u8` y `Option<&u8>` = 8, `TresCasos` = 16, `String` y `Option<String>` = 24, `Option<*const u8>` = 16; los demás no cambian (comprobado con `size_of` en rustc 1.99.1 para `x86_64-pc-windows-msvc`).

## Bajo el capó

<BajoElCapo>

La regla general para un enum con datos en `repr(Rust)`:

1. Si alguna variante tiene un campo con nichos suficientes para las demás, la etiqueta se **esconde** en ese campo (`Option<&u8>`, `Option<bool>`, `Option<String>`).
2. Si no, se añade una etiqueta (normalmente 1 byte) y luego se redondea el tamaño al **alineamiento** más exigente. Por eso `Option<u8>` = 2 pero `Option<u32>` = 8 (4 de datos + 1 de etiqueta + 3 de relleno).

La documentación de `Option` **garantiza** el caso de las referencias, `Box`, `NonNull` y los `NonZero*`: `Option<&T>` tiene el mismo tamaño y representación que un puntero que puede ser nulo. Para el resto de enums, el layout de `repr(Rust)` **no está garantizado** (el compilador puede cambiarlo entre versiones); si necesitas una forma fija, existen `#[repr(u8)]` y `#[repr(C)]` (mundo 22). Para ver el layout real hay una herramienta de nightly: `-Zprint-type-sizes`.

`Option<String>` ocupa lo mismo que `String` porque el puntero interno de un `String` es `NonNull` (nunca nulo). Y los punteros crudos `*const T` **sí** pueden ser nulos: no tienen nicho y `Option<*const u8>` necesita etiqueta.

</BajoElCapo>
