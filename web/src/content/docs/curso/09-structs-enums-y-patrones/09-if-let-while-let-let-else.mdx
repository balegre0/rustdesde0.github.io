## La idea

Un `match` con un solo caso interesante y un `_ => {}` es mucho ruido. Para eso hay atajos:

- **`if let PATRÓN = valor { … } else { … }`** — si encaja, entra y tienes las variables del patrón; si no, va al `else` (opcional). No hace falta cubrir todos los casos: el `else` es «todo lo demás».
- **`while let PATRÓN = valor { … }`** — repite mientras encaje. Ideal para vaciar una pila o leer hasta que no quede nada.
- **`let PATRÓN = valor else { …salir… };`** (estable desde Rust 1.65) — «sácame esto o me voy». Si encaja, las variables quedan disponibles **en el resto de la función**; si no, el `else` tiene que **salir**: `return`, `break`, `continue` o un pánico. Evita la «escalera» de `if let` anidados.

Y en la edición 2024 hay **cadenas de let** (*let chains*, Rust 1.88): `if let Some(u) = a && let Some(p) = b && p > 100 { … }` junta varias condiciones en una.

## Bajo el capó

<BajoElCapo>

Ninguno de estos atajos es magia: el compilador los traduce a un `match`. `if let P = v { A } else { B }` es `match v { P => A, _ => B }`. Por eso las reglas son las mismas (préstamos, movimientos y modos de enlace de la lección 8).

`let` normal exige un patrón **irrefutable** (*irrefutable*): uno que encaje siempre, como `(a, b)` sobre una tupla o `Punto { x, y }` sobre un struct. Un patrón que puede fallar, como `Some(n)`, es **refutable**, y solo vale donde haya un camino para el fallo: `if let`, `while let`, `match` o `let else`. El tipo del bloque `else` de un `let else` es `!` (el tipo «nunca»: una expresión que no termina normalmente); por eso el compilador puede garantizar que después del `let else` la variable existe.

</BajoElCapo>
