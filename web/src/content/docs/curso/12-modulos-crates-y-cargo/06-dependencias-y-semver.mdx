Usar bibliotecas de otros es lo que hace productivo a Rust: hay más de 150 000 crates en crates.io. Pero las bibliotecas cambian. Esta lección explica cómo Cargo decide **qué versión** usar y cómo evita que una actualización te rompa el programa.

## La idea

Las versiones de los crates siguen el **versionado semántico** (*semver*): `MAYOR.MENOR.PARCHE`.

| Sube… | Cuando… | Ejemplo |
|---|---|---|
| PARCHE | se arregla un fallo sin cambiar la interfaz | 1.4.2 → 1.4.3 |
| MENOR | se añade algo, sin romper lo existente | 1.4.3 → 1.5.0 |
| MAYOR | se rompe algo (se quita o cambia una función…) | 1.5.0 → 2.0.0 |

En `Cargo.toml`, `serde = "1.0.200"` **no** significa «exactamente esa». Significa «cualquier versión **compatible**»: de 1.0.200 en adelante, sin llegar a 2.0.0. Es lo mismo que escribir `"^1.0.200"`.

Con versiones `0.x`, la regla cambia: el número **menor** hace de mayor. `rand = "0.9"` acepta 0.9.x, pero **no** 0.10, porque antes de la 1.0 cualquier versión menor puede romper cosas.

Otros requisitos posibles: `"=1.2.3"` (exacta), `">=1.2, <1.5"` (rango), `"1.2.*"`. Úsalos poco: el requisito por defecto es casi siempre el correcto.

## Cargo.lock: la foto exacta

La primera vez que compilas, Cargo elige la versión más nueva que cumple cada requisito y la apunta en **`Cargo.lock`**. A partir de ahí usa **siempre esa**, aunque salgan versiones nuevas. Así, tu programa compila hoy y dentro de un año exactamente igual.

Para actualizar a propósito:

```powershell
cargo update             # todas las dependencias, dentro de los requisitos
cargo update -p serde    # solo una
cargo tree               # ver el árbol completo
cargo tree -d            # ver dependencias duplicadas (dos versiones del mismo crate)
```

## Bajo el capó

<BajoElCapo>

**El resolutor.** Cargo tiene que elegir una versión para cada crate de **todo** el árbol de forma que se cumplan todos los requisitos a la vez. Si dos dependencias piden versiones **compatibles** del mismo crate (`^1.2` y `^1.5`), elige una sola (la 1.5.x más nueva). Si piden versiones **incompatibles** (`^1` y `^2`), compila las dos: son crates distintos para el compilador, y sus tipos no se pueden mezclar.

**Desde Rust 1.84, el resolutor tiene en cuenta `rust-version`**: si un paquete declara la versión mínima de Rust que necesita, Cargo prefiere versiones de las dependencias que funcionen con ella. Es el comportamiento por defecto en los paquetes de la edición 2024.

**Ojo con la seguridad.** Una dependencia es código de otro que se ejecuta con tus permisos (y algunos crates ejecutan código al compilar, como verás con `build.rs`). Antes de añadir una, mira cuántas descargas tiene, quién la mantiene y cuándo se actualizó. En el mundo 16 verás `cargo audit` y `cargo deny`, que avisan de vulnerabilidades conocidas.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Pensar que «1.0» significa la versión 1.0">

❌ Escribir `serde = "1.0"` y creer que usarás la 1.0.0. Usarás la 1.x más nueva que haya cuando se cree el `Cargo.lock`.

✅ Si un día una actualización «compatible» rompe algo (pasa poco, pero pasa), tu `Cargo.lock` te protege: vuelve a la versión anterior con `cargo update -p nombre --precise 1.0.199` y avisa al autor del crate.

</Trampa>
