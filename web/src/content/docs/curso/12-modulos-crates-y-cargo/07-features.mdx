Muchos crates tienen partes que no todo el mundo necesita: soporte para un formato, una integración, colores en la terminal. Compilarlo todo siempre haría los programas más lentos de compilar y más grandes. Las **features** son la solución.

## La idea

Una **feature** es un interruptor de compilación con nombre. Se declara en el `Cargo.toml` del crate:

```toml
[features]
default = ["colores"]        # las que se activan si no dices nada
colores = []                 # una feature sin más efecto que el interruptor
json = ["dep:serde_json"]    # activa una dependencia opcional

[dependencies]
serde_json = { version = "1", optional = true }
```

Y quien la usa la activa al declarar la dependencia:

```toml
[dependencies]
mi_crate = { version = "1", features = ["json"] }
mi_crate_sin_nada = { version = "1", default-features = false }
```

En el código, la feature se consulta con `cfg`:

- `if cfg!(feature = "colores") { … }`: una **expresión** que vale `true` o `false`. Las dos ramas existen y se compilan.
- `#[cfg(feature = "colores")]` sobre una función, un módulo o una sentencia: si la feature no está activa, ese código **ni se compila**.

## Bajo el capó

<BajoElCapo>

**Unificación.** Si en tu árbol de dependencias dos crates usan `serde`, uno con la feature `derive` y otro sin ella, Cargo compila `serde` **una sola vez** con la **unión** de las features. Por eso las features tienen que ser **aditivas**: activar una solo puede **añadir** cosas, nunca quitar ni cambiar el comportamiento de otras. Una feature `sin_std` que desactivara cosas rompería a quien sí las usa.

**`--check-cfg`.** Desde Rust 1.80, el compilador avisa si consultas una feature (o cualquier `cfg`) que no está declarada: un error de escritura como `feature = "color"` ya no pasa desapercibido. Cargo le pasa automáticamente la lista de features válidas.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Features que se excluyen entre sí">

❌ Dos features `backend-a` y `backend-b` que no pueden estar activas a la vez. Por la unificación, cualquier día algún crate del árbol activará una y otro la otra, y tu crate no compilará (o hará algo raro).

✅ Si de verdad son alternativas, deja que se puedan activar las dos y elige en el código (por ejemplo, con una función de configuración), o usa crates separados.

</Trampa>
