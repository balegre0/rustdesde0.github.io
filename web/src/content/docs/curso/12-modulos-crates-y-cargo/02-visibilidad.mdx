La visibilidad es la herramienta que te deja cambiar el interior de tu código sin romper a quien lo usa. En Rust la regla por defecto es la más prudente: **todo es privado**.

## La idea

Un elemento **privado** (sin `pub`) solo es visible para su propio módulo y para los módulos que tiene **dentro**. Para que se vea desde fuera, hay que marcarlo con `pub`, y **todo el camino** tiene que ser visible: de nada sirve una función `pub` dentro de un módulo privado.

Hay grados intermedios:

| Escribes | Visible para |
|---|---|
| (nada) | el módulo actual y sus descendientes |
| `pub(super)` | además, el módulo padre |
| `pub(crate)` | todo el crate, pero no otros crates |
| `pub` | todo el mundo, también otros crates |

**Los campos de un struct van aparte.** Un `pub struct` tiene campos privados salvo que les pongas `pub` uno a uno. Es la forma de proteger un **invariante**: si `saldo` es privado, solo los métodos de `banco` pueden cambiarlo, y nadie puede poner un saldo imposible desde fuera.

<NoCompila ej="m12/campo-privado-mal" explicacion="`saldo` es privado: solo el módulo `banco` puede tocarlo. Desde `main`, el único camino es un método público, como `ingresar`." />

(En un `pub enum`, en cambio, todas las variantes son públicas: un enum con variantes ocultas no se podría usar en un `match`.)

## Bajo el capó

<BajoElCapo>

**La privacidad es por módulo, no por tipo.** No hay nada como «privado para todos menos este struct»: cualquier código del mismo módulo (o de sus descendientes) ve todo. Por eso, en Rust, el **módulo** es la frontera de encapsulación.

**Constructores obligatorios.** Si un struct tiene algún campo privado, desde fuera **no** se puede crear con `Cuenta { … }`, porque harían falta todos los campos. Hay que pasar por una función del módulo, como `Cuenta::nueva`. Esa es la forma idiomática de garantizar que todos los valores se crean válidos.

**`#[non_exhaustive]`.** En bibliotecas, este atributo en un struct o enum público impide que otros crates lo construyan o hagan `match` sin un brazo `_`. Así puedes añadir campos o variantes en el futuro sin romper a nadie (lección 12).

</BajoElCapo>

## Trampa típica

<Trampa titulo="Hacerlo todo pub para que compile">

❌ Poner `pub` en todos los campos y funciones a la primera queja del compilador. Funciona, pero cualquier código podrá cambiar cualquier cosa, y los invariantes desaparecen.

✅ Empieza con todo privado y abre solo lo que **otros** necesitan usar. Para cambiar un campo desde fuera, ofrece un método que compruebe que el cambio es válido.

</Trampa>
