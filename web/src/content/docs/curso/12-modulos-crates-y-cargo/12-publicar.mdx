Publicar un crate es compartir tu código con todos. Es fácil de hacer, pero tiene una consecuencia seria: otros programas empezarán a depender de ti. Esta lección es sobre las reglas que lo hacen funcionar.

## La idea

Un crate publicado necesita, en su `Cargo.toml`:

```toml
[package]
name = "conversor-unidades"
version = "0.1.0"
edition = "2024"
rust-version = "1.85"
description = "Convierte entre unidades de longitud, masa y temperatura."
license = "MIT OR Apache-2.0"
repository = "https://github.com/tu-usuario/conversor-unidades"
readme = "README.md"
keywords = ["unidades", "conversion"]
categories = ["science"]
```

`MIT OR Apache-2.0` es la doble licencia que usan el propio Rust y la mayoría de crates. Luego:

```powershell
cargo publish --dry-run   # comprueba todo sin subir nada
cargo login               # una vez, con un token de crates.io
cargo publish             # sube la versión
```

**Una versión publicada es para siempre.** No se puede borrar ni sustituir: así se garantiza que cualquier `Cargo.lock` del mundo siga funcionando. Si publicas una versión con un fallo grave, la **retiras** con `cargo yank --version 0.1.1`: nadie nuevo la elegirá, pero quien ya la tenía no se rompe.

## Elegir la siguiente versión

El versionado semántico (lección 6) es una **promesa** a quien te usa. Antes de publicar, pregúntate si el cambio puede romper código que hoy compila:

| Cambio | Versión |
|---|---|
| arreglar un fallo interno | PARCHE |
| añadir una función o un tipo públicos | MENOR |
| añadir una variante a un `pub enum` sin `#[non_exhaustive]` | **MAYOR** (rompe los `match` exhaustivos) |
| añadir un campo público a un struct sin `#[non_exhaustive]` | **MAYOR** (rompe a quien lo construye) |
| quitar, renombrar o cambiar la firma de algo público | **MAYOR** |
| implementar un trait nuevo para un tipo tuyo | normalmente MENOR |

La herramienta `cargo-semver-checks` compara tu crate con la última versión publicada y detecta muchos de estos cambios automáticamente.

## Bajo el capó

<BajoElCapo>

**Qué se sube.** `cargo publish` empaqueta el código en un archivo `.crate` (un `.tar.gz`) con `Cargo.toml` normalizado, y crates.io lo guarda junto con una entrada en su **índice**: la lista de versiones, dependencias y features de cada crate, que es lo que Cargo consulta para resolver versiones. Desde 1.70, Cargo descarga solo las partes del índice que necesita (protocolo *sparse*).

**Las dependencias de un crate publicado** solo pueden venir de crates.io (no por ruta ni de Git), para que cualquiera pueda compilarlo.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Publicar secretos o archivos enormes">

❌ Publicar sin mirar qué entra en el paquete: archivos de prueba gigantes, configuraciones locales o, peor, un archivo con claves.

✅ Antes de publicar, `cargo package --list` muestra exactamente qué archivos se subirán. Excluye lo que sobre con `exclude = […]` o `include = […]` en `[package]`. Y recuerda: lo publicado no se puede borrar.

</Trampa>
