## La idea

Una función es **recursiva** cuando se llama a sí misma. Suena a trampa, pero es una forma muy natural de pensar algunos problemas. Por ejemplo, el factorial: 5! = 5 × 4 × 3 × 2 × 1, que es lo mismo que **5 × 4!**. Si sabes calcular el factorial de 4, sabes el de 5.

Toda recursión necesita dos piezas. El **caso base**: una entrada tan sencilla que se responde directamente (0! = 1). Y el **caso recursivo**: la función se llama con un problema **más pequeño**, que la acerca al caso base (n! = n × (n − 1)!). Si falta el caso base, o el caso recursivo no se acerca a él, la función se llamaría para siempre.

Cada llamada es una llamada de verdad, con su propio espacio en la pila (lo verás en la siguiente lección). Las llamadas que esperan se van **apilando**, y se resuelven en orden inverso: la última en empezar es la primera en terminar.

## Bajo el capó

<BajoElCapo>

**Cada llamada ocupa pila.** Una llamada recursiva no es «volver al principio»: es una llamada nueva, con un marco nuevo, sus propios parámetros y su dirección de retorno. Si la recursión es muy profunda, la pila se llena. La pila del hilo principal tiene un tamaño fijo, decidido cuando arranca el programa (en el navegador, la pila de tus programas ocupa 1 MiB, como verás en la lección siguiente).

**Recursión sin caso base.** Si escribes `fn bajar(n: u64) -> u64 { 1 + bajar(n + 1) }`, el compilador lo detecta y avisa:

```text
warning: function cannot return without recursing
  |
2 | fn bajar(n: u64) -> u64 {
  | ^^^^^^^^^^^^^^^^^^^^^^^ cannot return without recursing
3 |     1 + bajar(n + 1)
  |         ------------ recursive call site
```

Si aun así lo ejecutas en el navegador, se detiene con «RangeError: Maximum call stack size exceeded» (se superó el tamaño máximo de la pila de llamadas). En un PC, el programa también se detiene por **desbordamiento de pila** (*stack overflow*): al final de la pila hay una zona de memoria protegida, y tocarla detiene el programa en vez de dejarle pisar otra memoria.

**El desbordamiento numérico tampoco se escapa.** 21! no cabe en un `u64`:

En modo debug, la multiplicación se comprueba y el programa entra en pánico: «attempt to multiply with overflow» (intento de multiplicar con desbordamiento), como viste en el mundo 03.

</BajoElCapo>

## Trampa típica

<Trampa titulo="El caso recursivo que no se acerca">

❌ Aquí hay caso base, pero `n + 1` se **aleja** de él: con `n = 3` nunca se llega a 0.

```rust
fn suma_hasta(n: u32) -> u32 {
    if n == 0 { 0 } else { n + suma_hasta(n + 1) }
}
```

✅ Cada llamada debe hacer el problema **más pequeño**: `n + suma_hasta(n - 1)`.

</Trampa>
