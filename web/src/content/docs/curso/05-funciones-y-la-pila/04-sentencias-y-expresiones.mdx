Vas a dominar la diferencia entre **sentencia** y **expresión** y a reconocer al instante el error más típico de quien empieza con funciones en Rust: el punto y coma que sobra.

## La idea

Repasemos con precisión, porque ahora importa:

- Una **expresión** produce un valor: `5`, `x * x`, `cuadrado(3)`, `if a { 1 } else { 2 }`, un bloque `{ ... }`. Se pueden anidar unas dentro de otras.
- Una **sentencia** es una orden completa que no produce valor útil. En Rust hay pocas: `let ...;`, las declaraciones como `fn`, y **cualquier expresión seguida de `;`**.

La última regla es la clave. El `;` toma una expresión, la ejecuta y **tira su valor**. Dentro de una función con `-> i32`, si la última línea es `x * x;`, el cálculo se hace... y el resultado se tira. El cuerpo se queda sin expresión final, vale `()`, y `()` no es un `i32`. Rust te lo dice con el error **E0308** (tipos que no coinciden) y una pista de oro: «remove this semicolon to return this value» (quita este punto y coma para devolver este valor).

Un truco para no fallar nunca: **la última línea de una función que devuelve algo no lleva `;`**. Todas las demás, sí.

## Pruébalo

<Ejecutar ej="m05/sentencias-y-expresiones" />

1. `((a * a + b * b) as f64).sqrt()` es una expresión dentro de otra: suma, conversión a `f64` y raíz cuadrada. 3, 4, 5: el triángulo de siempre.
2. El bloque que termina en una sentencia `let` vale `()`.
3. Sorpresa: `c = 10` también es una expresión, pero vale `()`, no 10. Asignar cambia `c`, pero no «devuelve» nada útil.

## Bajo el capó

<BajoElCapo>

**Cómo lee el compilador un cuerpo.** El cuerpo de una función es un bloque: una lista de sentencias y, opcionalmente, una expresión final. El tipo del bloque es el de esa expresión final, o `()` si no la hay. Luego el compilador compara ese tipo con el de la firma (`-> i32`). Si no coinciden, error E0308. Nada más: no hay magia, es la regla de los bloques del mundo 04.

**`let` no es una expresión.** Por eso no puedes escribir `let x = (let y = 5);`:

<NoCompila ej="m05/let-no-es-expresion" explicacion="«expected expression, found `let` statement»: esperaba una expresión y encontró una sentencia `let`. La nota menciona que `let` sí puede aparecer directamente en las condiciones de `if` y `while` (`if let`, que verás en el mundo 09)." />

**¿Por qué Rust lo diseñó así?** Hacer que casi todo sea una expresión permite escribir `let x = if ... { } else { };` o `let y = match ...` sin variables a medio inicializar. Y que el `;` descarte el valor te obliga a decidir: o quieres el valor (sin `;`) o no (con `;`). El compilador comprueba que tu decisión cuadre con la firma.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Añadir return en vez de quitar el ;">

❌ Ante el error, mucha gente escribe `return x * x;`. Compila, pero no es lo habitual en Rust:

```rust
fn cuadrado(x: i32) -> i32 {
    return x * x;
}
```

✅ Basta con quitar el punto y coma. Reserva `return` para salir **antes** del final:

```rust
fn cuadrado(x: i32) -> i32 {
    x * x
}
```

</Trampa>
