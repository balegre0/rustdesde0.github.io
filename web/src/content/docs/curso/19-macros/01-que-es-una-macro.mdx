## Predice

<NoCompila ej="m19/formato-mal" explicacion="El texto tiene dos huecos `{}` pero solo pasas un argumento. Lo detecta el compilador, sin ejecutar el programa: `println!` revisa el texto de formato mientras compila." />

¿Cómo puede el compilador saber que faltan argumentos si `println!` todavía no se ha ejecutado? Una función normal no podría: recibe valores cuando el programa ya está en marcha. Una **macro** (*macro*) trabaja antes.

## La idea

Una macro es un trozo de programa que el compilador ejecuta **mientras compila**. Recibe código (en forma de *tokens*) y devuelve más código, que ocupa el lugar de la llamada. A ese proceso se le llama **expansión** (*macro expansion*).

Un **token** (*token*) es la pieza mínima del código: un nombre (`x`), un número (`5`), un símbolo (`+`, `=`), un texto (`"hola"`)… Los espacios y los saltos de línea no son tokens; solo separan.

Esto da a las macros dos poderes que una función no tiene:

1. **Número de argumentos variable**: `println!("a")`, `println!("{}", 1)`, `println!("{} {}", 1, 2)`. Las funciones de Rust tienen siempre un número fijo.
2. **Mirar el código antes de que exista el programa**: `println!` lee el texto de formato y comprueba que cada `{}` tiene su argumento.

## Bajo el capó

<BajoElCapo>
El compilador procesa tu programa por fases. Las macros se expanden muy pronto:

1. **Análisis léxico**: el texto se parte en tokens.
2. **Análisis sintáctico**: los tokens forman un árbol (el AST, *abstract syntax tree*). Cuando aparece `nombre!(...)`, lo que hay dentro de los paréntesis se guarda **sin interpretar**, como un árbol de tokens (*token tree*).
3. **Expansión de macros**: cada invocación se sustituye por el código que produce. Si ese código contiene más macros, se expanden también.
4. Solo **después** vienen la resolución de nombres, la comprobación de tipos, el borrow checker y la generación de código.

Por eso una macro no sabe de tipos: cuando se ejecuta, los tipos todavía no se han calculado. Lo que sí sabe es la *forma* del código.

Así queda `println!("v = {:?}", v)` después de expandirse (salida real de `rustc -Zunpretty=expanded` con Rust 1.99.1, que verás en la lección 10):

```rust
{ ::std::io::_print(format_args!("v = {0:?}\n", v)); };
```

`println!` se convierte en una llamada a una función interna (`_print`) con otra macro, `format_args!`, que es la que analiza el texto de formato. Como esa última está implementada dentro del propio compilador, puede dar el error de la sección *Predice*.

Un detalle: dentro de una invocación los paréntesis, corchetes y llaves deben ir **equilibrados**. `stringify!(a ( b)` no puede ni empezar a expandirse: el analizador léxico necesita saber dónde termina el árbol de tokens.
</BajoElCapo>

## Trampa típica

<Trampa titulo="«println! es una función»">
❌ Pensar que `println!` recibe valores como una función y que «imprimir mal» es un fallo que verás al ejecutar.

✅ `println!` es una macro: el formato se comprueba **al compilar**. Si el número de `{}` no cuadra con los argumentos, ni siquiera obtienes un programa. Es una ventaja: el error aparece antes de que nadie use tu programa.
</Trampa>

<Historia titulo="Por qué el `!`">
Desde antes de la versión 1.0 (2015), Rust marca las macros con `!` para que, al leer, sepas que esa línea puede hacer cosas que una función no puede: aceptar sintaxis propia o un número variable de argumentos.
</Historia>
