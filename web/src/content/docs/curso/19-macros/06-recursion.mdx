## La idea

Una macro puede invocarse a sí misma en su plantilla. El compilador sigue expandiendo hasta que no queda ninguna invocación. Con eso se pueden hacer cosas que una repetición `$(...)*` no puede: **acumular un resultado**, **invertir el orden** o **leer un mini-lenguaje** con palabras clave propias.

El patrón clásico es el **tt-muncher** («masticador de tokens»): cada regla reconoce unos pocos tokens del **principio** de la entrada, hace algo con ellos y se llama a sí misma con `$($resto:tt)*`. Cuando no queda nada, una regla final devuelve el resultado.

Para guardar resultados parciales se usan **reglas internas**: reglas que empiezan con un marcador como `@acc`. El usuario llama a la regla pública y esta pasa a las internas añadiendo el acumulador.

## Pruébalo

<Ejecutar ej="m19/tt-muncher" titulo="Un mini-lenguaje: sube y baja" />

1. La regla de entrada (`$($todo:tt)*`) mete un acumulador `0` y llama a las internas.
2. Cada regla interna mastica dos tokens (`sube 3`, `baja 1`) y vuelve a llamarse con el resto.
3. Cuando ya no queda nada, `(@acc $acc:expr;)` devuelve el acumulado.

## Bajo el capó

<BajoElCapo>
La expansión real (Rust 1.99.1) muestra lo que se construyó paso a paso:

```rust
{ ::std::io::_print(format_args!("{0}\n", (((0 + 3) - 1) + 2))); };
{ ::std::io::_print(format_args!("{0}\n", 0)); };
{ ::std::io::_print(format_args!("{0}\n", (0 - 5))); };
```

El «programa» `sube 3 baja 1 sube 2` se tradujo en compilación a una expresión aritmética. El cálculo final lo hace luego el compilador como con cualquier constante.

**Coste.** Cada paso de recursión es una expansión completa, y en cada una el compilador vuelve a comparar todos los tokens que quedan. Un tt-muncher sobre `n` tokens hace del orden de `n²` trabajo. Con entradas de cientos de tokens se nota en el tiempo de compilación.

**Límite.** Para no colgarse con una macro que nunca termina, el compilador corta a los **128** niveles de anidamiento (valor por defecto). Se puede subir con `#![recursion_limit = "256"]` al principio de la crate, pero si lo necesitas a menudo, probablemente tu macro debería procesar varios elementos por paso o ser una función.

**`@` como marcador.** Se usa `@` porque no puede empezar ninguna expresión ni ningún item: es imposible que una entrada normal del usuario encaje por error con una regla interna.
</BajoElCapo>

## Trampa típica

<NoCompila ej="m19/recursion-infinita" explicacion="La macro se llama a sí misma con una entrada que nunca se hace más pequeña: no hay ninguna regla de parada. El compilador se detiene al alcanzar el límite de recursión y sugiere subirlo, pero aquí subirlo no arreglaría nada. Toda macro recursiva necesita un caso base y que cada paso **consuma** entrada." />

<Trampa titulo="El orden de las reglas en un tt-muncher">
❌ Poner primero la regla de entrada `($($todo:tt)*)`: acepta cualquier cosa, incluidas las llamadas internas `@acc …`, y la macro se llamaría a sí misma sin fin.

✅ Las reglas internas, que son más concretas, primero; la de entrada, la última.
</Trampa>
