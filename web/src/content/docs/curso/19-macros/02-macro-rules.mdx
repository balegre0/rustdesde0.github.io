## La idea

Una macro declarativa se define con `macro_rules!`, un nombre y una lista de **reglas** (*rules*), también llamadas brazos, separadas por `;`:

```rust
macro_rules! nombre {
    (patrón 1) => { código generado 1 };
    (patrón 2) => { código generado 2 };
}
```

El **patrón** (*matcher*) describe qué tokens acepta la regla. Puede contener tokens literales, que deben aparecer tal cual (como el `0` de antes), y **metavariables** (*metavariables*) como `$nombre:expr`, que capturan un trozo de código de una clase concreta (aquí, una expresión). La **plantilla** (*transcriber*) es el código que se genera; dentro de ella, `$nombre` se sustituye por lo capturado.

El compilador prueba las reglas **en orden** y usa la primera que encaja. Si ninguna encaja, es un error de compilación.

## Pruébalo

<Ejecutar ej="m19/hola-macro" />

1. La primera regla no acepta nada: `saluda!()`.
2. La segunda captura una expresión cualquiera: un literal, un `String::from(...)`, lo que sea.
3. Los tres delimitadores `()`, `[]` y `{}` valen para invocar. Por costumbre se usan `()` para lo que parece una llamada, `[]` para colecciones (`vec![...]`) y `{}` para bloques de definiciones.

## Bajo el capó

<BajoElCapo>
Así queda `main` después de la expansión (salida real de `-Zunpretty=expanded`, Rust 1.99.1):

```rust
fn main() {
    { ::std::io::_print(format_args!("¡Hola, mundo!\n")); };
    { ::std::io::_print(format_args!("¡Hola, {0}!\n", "Lucía")); };
    {
        ::std::io::_print(format_args!("¡Hola, {0}!\n",
                String::from("Íñigo")));
    };
    { ::std::io::_print(format_args!("¡Hola, {0}!\n", "Mar")); }
}
```

No queda rastro de `saluda!`: cada invocación se reemplazó por el código de su regla, y luego `println!` se expandió a su vez. El programa que se comprueba y se compila es este.

Cómo se emparejan las reglas: el compilador recorre los tokens de la invocación y los del patrón a la vez. Un token literal tiene que coincidir exactamente. Una metavariable invoca al analizador sintáctico de Rust para leer un trozo de la clase pedida (una expresión, un tipo…). **No hay vuelta atrás dentro de una regla**: si el analizador empieza a leer una expresión y falla a mitad, la macro entera da error en lugar de probar la regla siguiente. Por eso conviene poner primero las reglas más específicas.
</BajoElCapo>
