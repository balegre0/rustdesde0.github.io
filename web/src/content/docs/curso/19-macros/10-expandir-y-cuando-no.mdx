## La idea

**Ver la expansión** es la mejor manera de entender (y depurar) una macro. Tienes tres formas:

1. **`cargo expand`**: herramienta de la comunidad que se instala aparte (`cargo install cargo-expand`) y usa la toolchain nightly para imprimir tu crate con todas las macros expandidas.
2. **El Rust Playground**: en el menú *Tools*, la opción *Expand macros*.
3. **Directamente con `rustc`**: `-Zunpretty=expanded` es la opción (inestable, solo nightly) que usan las dos anteriores. Todas las expansiones que has visto en este mundo salen de ahí.

**Cuándo no usar una macro.** Una macro es más difícil de leer, de documentar, de depurar y de entender para el editor (el autocompletado funciona peor dentro de sus argumentos). Sus errores son más confusos. Y, como acabas de ver, puede **evaluar un argumento varias veces**. La regla: si una función, un genérico, un trait o una closure resuelve el problema, usa eso. Reserva las macros para lo que solo ellas pueden hacer:

- número variable de argumentos o sintaxis propia (`vec!`, `println!`, un mini-lenguaje);
- generar items: structs, impls, funciones (repetir un `impl` para veinte tipos numéricos);
- trabajar en compilación con el código fuente (`stringify!`, `concat!`, comprobaciones con `compile_error!`).

## Pruébalo

<Ejecutar ej="m19/funcion-mejor" titulo="La versión con función" />

1. Como función genérica, el argumento se calcula **una vez**, antes de la llamada.
2. Los genéricos con traits (`Mul + Copy`) aceptan varios tipos, que era la otra razón para usar una macro.

## Bajo el capó

<BajoElCapo>
La expansión real de `doble-evaluacion.rs` (Rust 1.99.1) no deja lugar a dudas:

```rust
fn main() {
    let mut n = 0;
    let r = siguiente(&mut n) * siguiente(&mut n);
    { ::std::io::_print(format_args!("r = {0}, n = {1}\n", r, n)); };
}
```

La macro copió los tokens del argumento en cada aparición de `$x`. Si de verdad necesitas una macro aquí, la solución es evaluar una vez dentro de un bloque:

<Ejecutar ej="m19/cuadrado-una-vez" titulo="Evaluar el argumento una sola vez" />

(Gracias a la higiene, ese `v` no choca con ninguna variable del usuario.)

**Herramientas de depuración en nightly.** `trace_macros!(true);` imprime cada paso de expansión y `log_syntax!` imprime los tokens que recibe; las dos son inestables. En estable, el truco es reducir la macro y mirar la expansión.

**Rendimiento.** Una macro no hace tu programa más rápido que una función: el optimizador inserta (*inline*) las funciones pequeñas igualmente. Lo que sí hace es que se compile más código, porque cada invocación genera su propia copia.
</BajoElCapo>

## Trampa típica

<Trampa titulo="Una macro para ahorrarte escribir una función">
❌ `macro_rules! media { ($a:expr, $b:expr) => { ($a + $b) / 2.0 } }`: no aporta nada que no dé una función, evalúa cada argumento donde aparezca, no aparece bien en la documentación y sus errores apuntan dentro de la macro.

✅ `fn media(a: f64, b: f64) -> f64 { (a + b) / 2.0 }`: tipos claros, documentación, un error claro si te equivocas al llamarla.
</Trampa>
