Esta es una de las piezas más avanzadas del sistema de tipos, y llegó a Rust estable en 2022 (versión 1.65), tras años de trabajo. Sirve para un problema concreto que el trait `Iterator` no puede resolver.

## La idea

En `Iterator`, el tipo de los elementos es fijo:

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
}
```

`Item` no puede depender del préstamo de `self` en `next`. Por eso un iterador **no puede devolver préstamos de sí mismo**: por ejemplo, ventanas `&mut` que se solapan sobre su propio búfer. (Las devuelve de los datos que tiene prestados, como el `Cursor<'a>` del mundo 08, que no es lo mismo.)

Un **GAT** (*generic associated type*) es un tipo asociado con parámetros propios:

```rust
trait IteradorQuePresta {
    type Item<'a> where Self: 'a;
    fn siguiente(&mut self) -> Option<Self::Item<'_>>;
}
```

Ahora cada llamada a `siguiente` devuelve un `Item` atado al préstamo de **esa** llamada. Como el resultado mantiene prestado el iterador, no puede haber dos elementos vivos a la vez, y por eso es seguro que se solapen.

Cada ventana suma su primer elemento al segundo, y la siguiente ventana empieza donde estaba ese segundo: el resultado son las sumas acumuladas `[1, 3, 6, 10]`. Con `Iterator` sería imposible, porque devolver dos `&mut` solapados vivos a la vez violaría la regla de los préstamos.

## Bajo el capó

<BajoElCapo>

**No es `for` compatible.** El bucle `for` usa `Iterator`, así que un iterador con GAT se recorre con `while let Some(x) = it.siguiente()`. Tampoco tiene adaptadores (`map`, `filter`…) gratis: habría que escribirlos.

**Otros usos.** Los GATs sirven también para abstraer sobre punteros (`type Puntero<T>: Deref<Target = T>`, para elegir entre `Rc` y `Arc`) y para traits asíncronos que devuelven futuros que prestan. Durante años, `async fn` en traits se emulaba con GATs, hasta que Rust 1.75 la estabilizó directamente.

</BajoElCapo>
