En la lección 5 viste que `dyn Trait` llama a los métodos a través de una **vtable**. No todos los métodos caben en una vtable, y por eso no todos los traits se pueden usar con `dyn`. A esa propiedad se la llama **compatibilidad con dyn** (*dyn compatibility*; antes, *object safety*).

## Predice

<NoCompila ej="m13/no-dyn" explicacion={"El método `guardar` es genérico en `T`. Piensa en la vtable: es una tabla con **un** puntero por método. ¿Cuántas versiones de `guardar` habría que meter en ella?"} />

## La idea

Una vtable tiene un puntero a función **por cada método**, y se construye al compilar para cada tipo concreto. Un método no cabe si:

- **Es genérico** (`fn guardar<T>(…)`): habría una versión por cada `T` posible, infinitas.
- **Devuelve `Self` o lo recibe por valor** (`fn clonar(&self) -> Self`): quien llama a través de `dyn` no sabe el tamaño de `Self`.
- **No tiene `self`** (`fn nuevo() -> Self`): no hay ningún valor del que sacar la vtable.

Y un trait no es compatible si exige `Self: Sized`, por ejemplo al tener `Clone` como supertrait:

<NoCompila ej="m13/clonar-dyn" explicacion="`Clone::clone` devuelve `Self` por valor, así que `Clone` exige `Sized`, y un `dyn Figura` no tiene tamaño conocido. La solución habitual es un método propio: `fn clonar_caja(&self) -> Box<dyn Figura>`." />

**El arreglo más común**: marcar los métodos problemáticos con `where Self: Sized`. Siguen existiendo para los tipos concretos, pero no forman parte de la vtable:

```rust
trait Guardar {
    fn guardar_texto(&self, texto: &str);                 // cabe en la vtable
    fn guardar<T: Debug>(&self, cosa: T) where Self: Sized { // excluido de dyn
        self.guardar_texto(&format!("{cosa:?}"));
    }
}
```

## Bajo el capó

<BajoElCapo>

**La vtable de un supertrait.** La vtable de `dyn Mascota` contiene también los métodos de `Ser` y de `Debug`. El upcasting (estable desde Rust 1.86) consiste en encontrar, dentro de ella, la parte que corresponde a `Ser`: el compilador organiza las vtables para que eso sea un simple desplazamiento o un puntero guardado en la propia vtable.

**`dyn Trait` implementa `Trait`.** Para cada trait compatible, el compilador genera automáticamente `impl Trait for dyn Trait`. Por eso puedes pasar un `&dyn Forma` a una función genérica `fn f<T: Forma + ?Sized>(x: &T)`.

</BajoElCapo>
