## La idea

El jefe es un compilador de verdad, solo que pequeño. Tiene las mismas piezas que has estudiado:

1. **Lexer** (lección 2): caracteres → `Tok`.
2. **Parser con precedencias** (lección 2): tokens → `Ast`.
3. **Pasada de optimización** (lecciones 4 y 9): `plegar` calcula al compilar todo lo que no depende de la entrada.
4. **Codegen** (lección 9): el árbol se convierte en instrucciones para una **máquina de pila**: `Empuja(5)`, `CargaX`, `Opera('*')`.
5. **Ejecución**: un bucle que interpreta esas instrucciones, como hace una CPU con las suyas.

Lee el programa de arriba abajo y busca cada etapa. Después, en el reto, escribirás tú una pasada de optimización nueva.

## Bajo el capó

<BajoElCapo>

**La escalera hasta rustc.** Así se pasa, paso a paso, de este curso a contribuir al compilador:

1. **Ver los bytes**: tablas de «predice el tamaño» con `const _: () = assert!(…)` (lección 10).
2. **Ver el ensamblador**: compara un bucle `while`, un `for` y un `iter().sum()` con `--emit=asm` o en Compiler Explorer (godbolt.org); encuentra la comprobación de límites.
3. **Ver HIR y MIR**: desazucara `for`, `?` y `match`, y dibuja el grafo de MIR a mano (lecciones 3 y 4).
4. **Punteros gordos y vtables**: lee una vtable en el asm y escribe un `dyn` a mano (lección 11).
5. **Async por dentro**: un `Future` a mano y un ejecutor mínimo; mide tamaños (lección 12).
6. **Un asignador propio** con `GlobalAlloc` (mundo 22) y un **binario sin `std`** (mundo 23).
7. **Compilar rustc**. Clona `rust-lang/rust` y, dentro:

   ```bash
   ./x setup                 # elige el perfil «compiler»
   ./x check                 # comprobación rápida
   ./x build --stage 1       # compila el compilador
   rustup toolchain link stage1 build/host/stage1
   rustc +stage1 --version   # ¡tu propio rustc!
   ./x test tests/ui         # los tests de diagnósticos
   ```

   En Windows necesitas las herramientas de compilación de Visual Studio (la trampa del enlazador del mundo 0) y bastante disco y paciencia: la primera compilación tarda.
8. **Primer PR**: en el repositorio, busca issues con etiquetas `E-easy`, `E-mentor` o `E-help-wanted`, y `A-diagnostics`. Mejorar un mensaje de error es la puerta de entrada clásica: tocas una etapa concreta, añades un **test UI** (un `.rs` con su salida esperada `.stderr`) y el cambio es fácil de revisar. **Clippy** (un repositorio aparte) es un sitio más amable aún para empezar: cada lint es pequeña y autocontenida.
9. **Profundidad**: lee `rustc_borrowck`, `rustc_mir_transform` y `rustc_next_trait_solver`; sigue los objetivos del proyecto para 2026 (nuevo solver, Polonius, frontend paralelo, Cranelift) en https://rust-lang.github.io/rust-project-goals/.

**Dónde pedir ayuda.** El Zulip del proyecto (rust-lang.zulipchat.com), canales `#t-compiler` y `#t-compiler/help`. La *rustc-dev-guide* (rustc-dev-guide.rust-lang.org) es la referencia para todo lo anterior. Antes de un cambio grande, pregunta: alguien puede estar trabajando en ello o conocer una trampa.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Empezar por la parte más difícil del compilador">

❌ «Mi primera contribución será reescribir una parte del borrow checker.»

✅ Empieza por algo que se pueda revisar en una tarde: un diagnóstico más claro, un test que falta, una lint. Aprenderás el flujo (compilar, probar, `./x test`, revisión, CI) con poco riesgo. La profundidad llega sola después de varios PR pequeños.

</Trampa>

<Historia titulo="Los mensajes de error como producto">

Una parte enorme del trabajo en rustc no es hacer que acepte más programas, sino que **explique mejor** por qué rechaza los que rechaza. Las sugerencias `help:` con el arreglo exacto, las etiquetas que señalan el préstamo y el uso, el `rustc --explain E0502`… todo eso lo escribieron personas que empezaron, muchas veces, con un primer PR de diagnósticos.

</Historia>
