Vas a descubrir qué te deja hacer exactamente la palabra `unsafe`, y —más importante— todo lo que **no** cambia cuando la escribes.

## Predice

Este programa mete dos préstamos exclusivos dentro de un bloque `unsafe`. Mucha gente cree que `unsafe` «apaga las comprobaciones». ¿Por qué no compila entonces?

<NoCompila ej="m20/unsafe-no-apaga" explicacion="El bloque unsafe solo permite la desreferencia de `p`. Las reglas de préstamos siguen intactas: `a` y `b` serían dos préstamos exclusivos vivos a la vez, y eso es E0499 dentro o fuera de unsafe." />

## La idea

Rust es, en realidad, **dos lenguajes en uno**. El Rust *seguro* (el que llevas 19 mundos escribiendo) tiene una garantía fuerte: ningún programa que compile puede tener comportamiento indefinido. El Rust *inseguro* (*unsafe Rust*) añade un puñado de operaciones que el compilador **no puede comprobar**, y por eso te pide que las marques.

Esas operaciones extra son exactamente cinco, los «superpoderes»:

1. **Desreferenciar un puntero crudo** (`*const T` o `*mut T`).
2. **Llamar a una función `unsafe`** (incluidas las de otras bibliotecas a través de FFI).
3. **Leer o escribir un `static mut`**.
4. **Implementar un trait `unsafe`** (como `Send`, `Sync` o `GlobalAlloc`).
5. **Leer un campo de una `union`**.

Nada más. Dentro de `unsafe { }` los tipos se comprueban igual, los préstamos se comprueban igual y los tiempos de vida se comprueban igual. Lo único distinto es que esas cinco cosas pasan a estar permitidas… **bajo tu palabra**. `unsafe` no es un permiso, es una promesa: «yo garantizo que aquí se cumplen las condiciones que el compilador no ve». Si la promesa es falsa, el programa tiene UB.

## Pruébalo

Los cinco superpoderes, usados correctamente. Fíjate en que **crear** el puntero (`&raw const x`) no necesita `unsafe`: lo peligroso es **usarlo**.

<Ejecutar ej="m20/superpoderes" />

Cada bloque lleva un comentario `// SAFETY:` que explica por qué la promesa es cierta. No es decoración: es la prueba que otra persona (o tú dentro de un mes) leerá para auditar el código.

## Bajo el capó

<BajoElCapo>

**`unsafe` no existe en el binario.** No genera instrucciones, no activa ningún modo especial del procesador y no cuesta nada en tiempo de ejecución. Es información **para el compilador y para las personas**: delimita qué líneas dependen de una prueba manual.

**Dos papeles de la misma palabra:**

| Dónde | Qué significa | Quién tiene la obligación |
|---|---|---|
| `unsafe fn f()` | «llamarme exige condiciones» (se documentan en `# Safety`) | quien llama |
| `unsafe trait T` | «implementarme exige condiciones» | quien implementa |
| `unsafe { … }` | «aquí cumplo las condiciones» | quien escribe el bloque |
| `unsafe impl T for X` | «este tipo cumple las condiciones del trait» | quien escribe el `impl` |

Las dos primeras **declaran** una obligación; las dos últimas la **descargan**.

**Edición 2024.** Antes, el cuerpo entero de una `unsafe fn` contaba como un bloque `unsafe`. Desde la edición 2024 ya no: dentro de una `unsafe fn` cada operación peligrosa necesita su propio `unsafe { }`. Así queda marcada la línea exacta que hay que auditar. Si lo olvidas, `rustc` 1.99.1 avisa (es un aviso, no un error):

```text
warning[E0133]: dereference of raw pointer is unsafe and requires unsafe block
 --> unsafe-op-en-unsafe-fn.rs:3:5
  |
3 |     *p // operación insegura sin su propio `unsafe {}`
  |     ^^ dereference of raw pointer
  |
note: an unsafe function restricts its caller, but its body is safe by default
  = note: `#[warn(unsafe_op_in_unsafe_fn)]` (part of `#[warn(rust_2024_compatibility)]`) on by default
```

</BajoElCapo>

## Trampa típica

<Trampa titulo="«Lo envuelvo en unsafe y el error desaparece»">

❌ Ante un error del borrow checker, rodear el código con `unsafe { }` **no arregla nada**: el error sigue ahí (lo viste en *Predice*). Y si consigues «engañarlo» con punteros crudos, has cambiado un error de compilación por comportamiento indefinido, que es muchísimo peor.

✅ Un error de préstamos casi siempre tiene solución segura: reordenar, usar `split_at_mut`, `Cell`/`RefCell`, índices o `clone`. `unsafe` es para lo que el compilador **no puede expresar**, no para lo que te ha rechazado.

</Trampa>
