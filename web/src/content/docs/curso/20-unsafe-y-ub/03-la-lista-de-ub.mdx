## La idea

**Comportamiento indefinido** no es «el programa hace algo raro». Es que **el programa no tiene significado**. El compilador optimiza dando por hecho que el UB nunca ocurre; si ocurre, el resultado puede ser cualquier cosa: valores imposibles, ramas que se saltan, o efectos en líneas *anteriores* a la que tiene el fallo. Por eso «en mi máquina funciona» no prueba nada.

La Reference de Rust mantiene una **lista** (que ella misma avisa de que no es exhaustiva) de lo que se considera UB. Resumida:

| Grupo | Ejemplos de UB |
|---|---|
| Memoria | carreras de datos; leer o escribir por un puntero colgante o desalineado; proyecciones fuera de límites |
| Aliasing | romper las reglas de `&T` (mutar lo que apunta, salvo con `UnsafeCell`) y de `&mut T` (accederlo por un camino no derivado de él) |
| Inmutabilidad | mutar bytes inmutables (un `static` normal, algo alcanzado por `&T`, una constante) |
| Llamadas | ABI incorrecta; desenrollar un pánico por donde no se permite; ejecutar código con *target features* que la CPU no tiene |
| Intrínsecos | violar las precondiciones de `unreachable_unchecked`, `copy_nonoverlapping`, etc. |
| **Valores inválidos** | producir un valor que su tipo no admite (tabla de abajo) |

Y la otra mitad, igual de importante: **no son UB** el overflow de enteros (pánico en debug, vuelta en release), los *deadlocks*, las fugas de memoria, las condiciones de carrera lógicas o salir con `process::exit`. Son errores, pero el programa sigue teniendo significado. El Rust seguro puede tenerlos; lo que no puede tener es UB.

## Pruébalo

Cada tipo tiene un conjunto de patrones de bits permitidos. Las APIs seguras **comprueban** antes de producir el valor:

<Ejecutar ej="m20/valores-validos" />

Fíjate en `size_of Option<NonZeroU32> = 4` frente a `Option<u32> = 8`: como el 0 es un valor inválido para `NonZeroU32`, `Option` lo reutiliza para representar `None` (el *nicho*). Las reglas de validez no son solo prohibiciones: son las que permiten esa optimización.

## Bajo el capó

<BajoElCapo>

**La tabla de validez** (lo que nunca puede «existir»):

| Tipo | Valores válidos | Por qué importa |
|---|---|---|
| `bool` | `0x00` o `0x01` | el compilador puede usar los otros 254 patrones como nicho |
| `char` | `0..=0xD7FF` y `0xE000..=0x10FFFF` | por eso `Option<char>` mide 4 bytes |
| `&T`, `&mut T`, `Box<T>` | no nulos, alineados, sin colgar | `Option<&T>` usa el nulo como `None` |
| `fn(..)` | no nulo | `Option<fn()>` mide lo mismo que `fn()` |
| `enum` | solo discriminantes declarados | un `match` no necesita rama para «otro valor» |
| enteros, floats, punteros crudos | cualquier patrón… **inicializado** | memoria sin inicializar no es «basura»: es otra cosa (ver `MaybeUninit`) |
| `!` | ninguno | por eso una función `-> !` nunca vuelve |
| `str` | UTF-8 (invariante de **seguridad**, ver la lección 4) | |

**«Producir» un valor** significa asignarlo, leerlo, pasarlo a una función o devolverlo. Con el `transmute` de abajo, el UB ocurre en el momento en que existe ese `bool`, no cuando se usa.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Mirar la salida de un programa con UB">

❌ Este programa produce un `bool` con el byte `2`. Si lo ejecutas en una máquina normal puede imprimir «verdadero», «falso», o ambos en distintas compilaciones. **Ninguna de esas salidas significa nada**: no intentes razonar sobre ella.

```rust
let b: bool = unsafe { std::mem::transmute::<u8, bool>(2) }; // UB aquí mismo
```

✅ El ejemplo completo está en el Playground: ábrelo y elige *Tools → Miri*. Miri ejecuta el programa en una máquina abstracta que comprueba cada valor, y lo detiene en el `transmute` informando de que se ha construido un `bool` inválido. Y la versión correcta no necesita `unsafe`: un `match` sobre el byte, como `a_bool` en *Pruébalo*.

</Trampa>
