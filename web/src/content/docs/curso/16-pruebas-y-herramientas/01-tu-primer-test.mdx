Vas a escribir tu primera **prueba** (*test*): una función cuyo único trabajo es comprobar que otra hace lo que debe. La escribes una vez y la máquina la repite cada vez que cambies algo.

## Predice

Una prueba no es más que código que **entra en pánico si algo está mal**. La herramienta básica es `assert_eq!(a, b)`: si `a` y `b` son distintos, pánico. Este programa lo usa dentro de `main`:

## La idea

Hasta ahora comprobabas tu código **mirando** la salida. El problema es que mirar no escala: con veinte funciones y cien casos, nadie revisa todo después de cada cambio. Una prueba automatiza esa mirada. Escribes lo que *esperas* y el ordenador lo compara con lo que *pasa*.

En Rust, una prueba es una función normal con el atributo **`#[test]`** encima. Dentro llamas a tu código y compruebas el resultado con tres macros:

| Macro | Pasa si… | Si falla, muestra… |
|---|---|---|
| `assert!(cond)` | `cond` es `true` | la condición tal cual la escribiste |
| `assert_eq!(a, b)` | `a == b` | los dos valores, `left` y `right` |
| `assert_ne!(a, b)` | `a != b` | los dos valores |

Las tres aceptan además un **mensaje** con el mismo formato que `println!`: `assert!(x > 0, "x vale {x}")`. Una prueba **pasa** si termina sin pánico y **falla** si entra en pánico. No hay más magia: cualquier pánico cuenta, también un `unwrap()` sobre `None` o un índice fuera de rango.

## Pruébalo

Antes de llevarlas a un proyecto, mira las tres macros en un programa normal. Si todo se cumple, no dicen nada: solo hablan cuando algo va mal.

<Ejecutar ej="m16/asserts" />

Ahora, la forma de verdad. Cuando creas una biblioteca con `cargo new --lib calculo`, Cargo ya te escribe una prueba de ejemplo en `src/lib.rs`. La hemos traducido:

```rust title="src/lib.rs"
pub fn suma(a: u64, b: u64) -> u64 {
    a + b
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn suma_basica() {
        let resultado = suma(2, 2);
        assert_eq!(resultado, 4);
    }
}
```

Y en la terminal, `cargo test`. Esta es una salida real de un proyecto parecido, con seis pruebas (cuatro pasan, dos están marcadas para no ejecutarse; las verás en la lección siguiente):

## Bajo el capó

<BajoElCapo>

`#[test]` no es una palabra mágica del lenguaje: es un atributo que el compilador solo tiene en cuenta cuando compila **en modo prueba** (`rustc --test`, que es lo que hace `cargo test`). En ese modo pasan dos cosas:

1. Cada función `#[test]` se registra en una tabla estática con su nombre, su archivo, su línea y sus opciones (`ignore`, `should_panic`…).
2. Rust **sustituye tu `main`** por uno generado que llama al **arnés de pruebas** (*test harness*) de la biblioteca `test`, que recorre esa tabla.

Puedes verlo con la toolchain nightly y la opción `-Zunpretty=expanded`, que imprime el código después de expandir las macros. Para este archivo:

```rust
fn doble(x: i32) -> i32 { x * 2 }

#[test]
fn doble_de_dos() {
    assert_eq!(doble(2), 4);
}
```

`rustc +nightly --edition 2024 --test -Zunpretty=expanded` (nightly 1.101) produce, entre otras cosas:

```rust title="expansión real (recortada)"
extern crate test;
#[rustc_test_marker = "doble_de_dos"]
pub static doble_de_dos: test::TestDescAndFn =
    test::TestDescAndFn {
        desc: test::TestDesc {
            name: test::StaticTestName("doble_de_dos"),
            ignore: false,
            source_file: "exp.rs",
            start_line: 4usize,
            should_panic: test::ShouldPanic::No,
            // …más campos…
        },
        testfn: test::StaticTestFn(#[coverage(off)] ||
                test::assert_test_result(doble_de_dos())),
    };
fn doble_de_dos() {
    {
        match (&doble(2), &4) {
            (left_val, right_val) => {
                if !(*left_val == *right_val) {
                    let kind = ::core::panicking::AssertKind::Eq;
                    ::core::panicking::assert_failed(kind, &*left_val,
                        &*right_val, ::core::option::Option::None);
                }
            }
        }
    };
}
#[rustc_main]
pub fn main() -> test::ExitCode { test::test_main_env_args(&[&doble_de_dos]) }
```

Fíjate en tres detalles. `assert_eq!` toma **préstamos compartidos** de los dos lados (`&doble(2)`, `&4`): comparar no consume tus valores. Compara con `==`, así que el tipo necesita `PartialEq`. Y si falla, pasa los dos valores a `assert_failed`, que los imprime con `{:?}`: por eso también necesita `Debug`.

Si compilas el mismo archivo **sin** `--test`, la función `doble_de_dos` desaparece entera del programa: las pruebas no ocupan ni un byte en tu ejecutable final.

</BajoElCapo>
