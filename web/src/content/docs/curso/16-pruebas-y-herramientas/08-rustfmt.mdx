## La idea

**rustfmt** es el formateador oficial: lee tu código y lo vuelve a escribir siguiendo la **guía de estilo de Rust** (*Rust Style Guide*). Viene con rustup (componente `rustfmt`) y se usa con dos comandos:

- **`cargo fmt`**: formatea todos los archivos del proyecto, en el sitio.
- **`cargo fmt --check`**: no toca nada; dice qué cambiaría y termina con error si hay algo sin formatear.

La ventaja no es que su estilo sea «el mejor», sino que es **el de todos**. Cualquier proyecto en Rust que abras tendrá el mismo aspecto, y en una revisión de código nadie gasta tiempo en espacios. Muchos editores (con rust-analyzer) lo ejecutan al guardar.

## Pruébalo

Este es `cargo fmt --check` sobre el programa de arriba (salida real; la ruta del principio, acortada). Las líneas con `-` son las actuales; las de `+`, cómo quedarían:

```text title="cargo fmt --check (salida real)"
Diff in …\fmt1\src\main.rs:1:
-fn main(){
-let notas=vec![7,5,9];
-    let total:i32=notas.iter().sum();
-  if total>20{println!("¡buen trimestre! {}",total);}
+fn main() {
+    let notas = vec![7, 5, 9];
+    let total: i32 = notas.iter().sum();
+    if total > 20 {
+        println!("¡buen trimestre! {}", total);
+    }
 }
```

Termina con **código de salida 1**: así un servidor de integración continua sabe que alguien subió código sin formatear y marca el cambio en rojo. Tras `cargo fmt`, el archivo queda exactamente como las líneas `+`, y `cargo fmt --check` ya no dice nada y termina con 0.

Puedes ajustar algunas opciones con un archivo `rustfmt.toml` en la raíz del proyecto. Por ejemplo, con `max_width = 40` (el ancho máximo de línea; por defecto 100), rustfmt parte el `println!` (real):

```rust
fn main() {
    let notas = vec![7, 5, 9];
    let total: i32 = notas.iter().sum();
    if total > 20 {
        println!(
            "¡buen trimestre! {}",
            total
        );
    }
}
```

La mayoría de proyectos no tiene `rustfmt.toml`: usar el estilo por defecto es justo lo que hace que todo el código en Rust se parezca.

## Bajo el capó

<BajoElCapo>

rustfmt **no compila** tu programa. Lee el texto y construye el **árbol de sintaxis** (*AST*), la misma estructura que crea el compilador en su primer paso, y después lo vuelve a imprimir con sus reglas. No resuelve nombres ni comprueba tipos. Dos consecuencias que puedes ver de verdad:

- Un programa con un **error de tipos** se formatea sin problema. `fn main(){let x:u8="hola";println!("{x}");}` sale bien formateado y rustfmt termina con 0, aunque el programa no compile.
- Un programa con un **error de sintaxis** no se puede formatear, porque no hay árbol que reimprimir. Con `fn main(){let x = ;}` rustfmt termina con 1 y el error `expected expression, found ;`.

Como trabaja sobre el árbol, rustfmt sabe que dentro de `println!(…)` hay argumentos separados por comas, pero el interior de una macro hecha con `macro_rules!` con sintaxis propia a menudo lo deja tal cual: no siempre sabe qué forma tiene. Los comentarios los conserva.

El estilo depende de la **edición de estilo** (*style edition*): con la edición 2024 llegó el estilo 2024, con algunos cambios pequeños respecto al anterior. Por defecto se toma de la edición de tu `Cargo.toml`.

</BajoElCapo>

## Trampa típica

<Trampa titulo="La tabla alineada a mano que rustfmt aplasta">

❌ Escribes una matriz bien alineada y rustfmt la junta en una sola línea, porque cabe en el ancho máximo (real):

```rust
const OTRA: [[i32; 3]; 3] = [[1, 0, 0], [0, 1, 0], [0, 0, 1]];
```

✅ `#[rustfmt::skip]` le dice que no toque ese elemento. Úsalo poco, solo donde la forma visual tenga significado:

```rust
#[rustfmt::skip]
const MATRIZ: [[i32; 3]; 3] = [
    [1, 0, 0],
    [0, 1, 0],
    [0, 0, 1],
];
```

</Trampa>
