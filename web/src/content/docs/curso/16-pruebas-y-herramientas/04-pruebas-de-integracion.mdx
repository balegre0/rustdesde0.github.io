Las pruebas unitarias miran cada pieza por dentro. Ahora vas a probar tu biblioteca **desde fuera**, exactamente como la usará quien la descargue: solo con lo que es público.

## Predice

Aquí un módulo hace el papel de tu biblioteca y `main` el de un archivo de pruebas que la usa desde fuera. ¿Por qué no compila?

<NoCompila ej="m16/privada" explicacion="`suma` no es `pub`, así que desde fuera del módulo `notas` no existe: E0603 «function `suma` is private». Una prueba de integración está en la misma situación, porque es otro crate. Lo privado se prueba desde dentro (el arreglo lo muestra con una función dentro del módulo)." />

## La idea

Un proyecto con biblioteca tiene esta forma:

```text
notas/
├── Cargo.toml
├── src/
│   └── lib.rs          ← tu biblioteca, con sus pruebas unitarias dentro
└── tests/
    └── uso_publico.rs  ← pruebas de integración
```

Cargo trata cada archivo de `tests/` como **un crate independiente** que depende de tu biblioteca, igual que dependería de un crate descargado. Consecuencias:

1. Tienes que importar con el nombre del crate: `use notas::media;`.
2. Solo ves lo `pub`. Si un archivo de `tests/` necesita algo privado, a lo mejor tu API pública no basta para usar la biblioteca: es una pista de diseño.
3. No hace falta `#[cfg(test)]`: Cargo solo compila `tests/` cuando ejecutas pruebas.

Las pruebas unitarias responden a «¿esta pieza funciona?». Las de integración, a «¿las piezas funcionan **juntas**, a través de la puerta de entrada que ofrezco?».

## Pruébalo

Un archivo de integración real para la biblioteca de notas de las lecciones anteriores:

```rust title="tests/uso_publico.rs"
use notas::{aprobado, media, parsear};

#[test]
fn flujo_completo() {
    let textos = ["4", "6.5", "9"];
    let valores: Vec<f64> = textos.iter().map(|t| parsear(t).unwrap()).collect();
    let m = media(&valores).unwrap();
    assert!(aprobado(m));
}

#[test]
fn texto_invalido_da_error() {
    assert!(parsear("siete").is_err());
    assert!(parsear("11").is_err());
}
```

## Bajo el capó

<BajoElCapo>

Mira las rutas de las líneas `Running`: `deps\notas-084254e7a6508a54` y `deps\uso_publico-bdc34728528518b3`. Son **dos programas distintos**, cada uno con su propio `main` generado por el arnés. El número largo es un hash que Cargo añade para distinguir versiones de cada compilación.

El orden de compilación es:

1. Tu biblioteca, compilada normalmente (como `.rlib`, el formato de biblioteca de Rust).
2. Tu biblioteca otra vez, **con `--test`**: el programa de pruebas unitarias.
3. Cada archivo de `tests/`, con `--test`, enlazado contra la biblioteca del paso 1. Como ese paso se compiló **sin** `cfg(test)`, desde `tests/` tampoco existe tu módulo `tests` ni nada marcado con `#[cfg(test)]`.

Por eso las pruebas de integración son más lentas de compilar: cada archivo es un ejecutable más que enlazar. En proyectos grandes se suele tener un único `tests/integracion/main.rs` con submódulos, en vez de veinte archivos sueltos.

Si tu crate es **solo un binario** (`src/main.rs`), no hay biblioteca que enlazar y `tests/` no puede usar nada de él. El patrón de costumbre es poner la lógica en `src/lib.rs` y dejar `main.rs` en unas pocas líneas que llaman a la biblioteca: así todo es probable.

</BajoElCapo>

## Trampa típica

<Trampa titulo="El archivo de ayudas que se convierte en pruebas">

❌ Pones funciones auxiliares en `tests/comun.rs`. Cargo lo trata como **otro archivo de pruebas** y lo ejecuta (salida real):

```text
     Running tests\comun.rs (target\wasm32-wasip1\debug\deps\comun-b6c980a1e9423472.wasm)

running 0 tests

test result: ok. 0 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s
```

✅ Ponlas en una **subcarpeta**: `tests/comun/mod.rs`. Cargo no compila las subcarpetas de `tests/` como pruebas por su cuenta; las usas con `mod comun;`:

```rust title="tests/con_ayuda.rs"
mod comun;

#[test]
fn media_de_ejemplo() {
    let v = comun::notas_de_ejemplo();
    assert!(notas::media(&v).unwrap() > 6.0);
}
```

Con este cambio, el bloque `Running tests\comun.rs` desaparece y aparece `Running tests\con_ayuda.rs` con su prueba `media_de_ejemplo ... ok`.

</Trampa>
