Un microcontrolador no tiene sistema operativo: no hay nadie que abra archivos, cree hilos o imprima en una pantalla. Rust se adapta a eso con un solo atributo.

## La idea

La biblioteca estándar está hecha en **tres capas**:

| Capa | Necesita | Contiene |
|---|---|---|
| `core` | nada | tipos primitivos, `Option`, `Result`, iteradores, slices, `str`, `fmt`, `mem`, `ptr`, atómicos, `cell` |
| `alloc` | un asignador de memoria | `Box`, `Vec`, `String`, `Rc`, `Arc`, `BTreeMap` |
| `std` | un sistema operativo | archivos, hilos, red, `println!`, `HashMap`, tiempo, entorno |

`std` reexporta todo lo de `core` y `alloc`: por eso `std::option::Option` y `core::option::Option` son el mismo tipo.

`#![no_std]` al principio del crate dice: «no enlaces `std`». El crate puede usar todo `core`, y `alloc` si añade `extern crate alloc;` y alguien proporciona un asignador. Todo el lenguaje sigue igual: ownership, préstamos, traits, genéricos, closures, `async`.

## Bajo el capó

<BajoElCapo>

**Por qué casi todo cabe en `core`.** Lo que hace seguro a Rust (ownership, préstamos, tipos) se comprueba **al compilar** y no necesita nada al ejecutar. Por eso puedes tener las mismas garantías en un chip con 16 KB de RAM. Lo único que falta sin sistema operativo es lo que el sistema daba: memoria dinámica, entrada y salida, hilos.

**Los targets `none`.** Para microcontroladores se compila para targets como `thumbv7em-none-eabihf` (ARM Cortex-M4F) o `riscv32imc-unknown-none-elf`: el `none` del nombre es «sin sistema operativo». Esos targets solo traen `core` y `alloc` precompilados. Los enlaza `rust-lld`, el enlazador incluido en Rust, así que **no necesitan las Build Tools de Visual Studio**.

**Pánicos sin `std`.** Sin sistema operativo no hay quien imprima el mensaje ni desenrolle la pila: tú das un [`#[panic_handler]`](/ref/lenguaje/atributos/panic_handler/) y normalmente compilas con `panic = "abort"`.

</BajoElCapo>
