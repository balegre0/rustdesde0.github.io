## La idea

`.await` es un operador **sufijo**: va detrás de la expresión (`descarga().await`). Significa: «sondea este future; si no está listo, suspende **esta** función (devuelve `Pending` a quien nos sondea) y, cuando nos vuelvan a sondear, sigue sondeándolo; cuando esté listo, dame su valor».

Solo existe dentro de contextos async, que son tres:

- `async fn nombre(…) -> T` — una función cuyo resultado es un `impl Future<Output = T>`.
- `async { … }` — un **bloque async**: un future anónimo hecho en el sitio. Puede capturar variables, como una closure. Con `async move { … }`, las toma en propiedad.
- `async |args| …` — una **closure async** (Rust 1.85). Se pasa a funciones que piden `impl AsyncFn(A) -> B` (o `AsyncFnMut`, `AsyncFnOnce`, igual que con closures normales).

Detalle clave: `.await` de un future tras otro es **secuencial**. Para que dos futures avancen **a la vez** hace falta algo que los sondee intercalados (`join`, lección 9) o lanzarlos como tareas separadas (lección 8).

## Bajo el capó

<BajoElCapo>

**`.await` por dentro.** La Reference describe `fut.await` como, más o menos, este bucle dentro de la corrutina:

```rust
match IntoFuture::into_future(fut) {
    mut pinned => loop {
        match Pin::new_unchecked(&mut pinned).poll(cx) {
            Poll::Ready(r) => break r,
            Poll::Pending => yield, // aquí la función devuelve Pending y se suspende
        }
    }
}
```

Dos detalles: primero se llama a `IntoFuture::into_future`, así que puedes hacer `.await` sobre cualquier tipo que implemente `IntoFuture` (no solo sobre futures; útil para *builders*). Y el `Pin::new_unchecked` es seguro **aquí** porque la variable `pinned` vive dentro de la propia corrutina, que ya está fijada (lección 7). `Future` e `IntoFuture` están en el preludio desde la edición 2024 (en 2021 había que importarlos con `use std::future::Future;`).

**Por qué hacían falta las closures async.** Antes de 1.85 se escribía `|x| async move { … }`: una closure normal que devuelve un future. Eso tiene un límite: el future devuelto no puede tomar prestado nada **de la propia closure**, porque la closure y el future son dos valores separados. `AsyncFn` resuelve el préstamo: el future que produce `f(x)` puede usar lo que la closure capturó (en el ejemplo, `suma`), y la closure se puede llamar varias veces.

**Orden de evaluación.** En `a().await + b().await`, primero se crea y espera `a()`, después `b()`. Rust evalúa de izquierda a derecha, también con `.await`.

</BajoElCapo>

## Trampa típica

<Trampa titulo="Creer que crear futures los lanza">

❌ Esto **no** descarga en paralelo:

```rust
let f1 = descargar(url1);
let f2 = descargar(url2);
let r1 = f1.await; // descarga 1 entera...
let r2 = f2.await; // ...y luego la 2
```

✅ Para que avancen a la vez, júntalos con un `join` (`let (r1, r2) = join(f1, f2).await;`, lección 9) o lánzalos como tareas en tu ejecutor (`tokio::spawn`, lección 8).

</Trampa>
