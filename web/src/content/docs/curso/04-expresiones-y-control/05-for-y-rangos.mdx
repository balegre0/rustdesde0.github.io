## La idea

`for x in algo { ... }` ejecuta el cuerpo **una vez por cada elemento** de `algo`, y en cada vuelta `x` es el elemento de turno. Ese «algo» puede ser un **rango** de números, un array, un texto (con `.chars()`) y, más adelante, cualquier colección.

Un **rango** (*range*) se escribe `inicio..fin` y contiene los números desde `inicio` hasta `fin` **sin incluirlo**. Si quieres incluir el final, usa `inicio..=fin`. ¿Por qué excluir el final por defecto? Porque así `0..n` da **exactamente n números**, y `0..array.len()` recorre justo las posiciones válidas de un array.

Los rangos tienen trucos: `.rev()` los recorre al revés y `.step_by(k)` salta de k en k. Son **métodos** (funciones que se llaman con un punto); los verás con detalle en el mundo 14.

## Pruébalo

<Ejecutar ej="m04/for-array" />

1. `for nota in notas` recorre los cuatro elementos. No hay ningún índice que gestionar ni que se pueda salir.
2. Cuando también necesitas la posición, `.iter().enumerate()` te da parejas `(posición, elemento)`.
3. `"año".chars()` recorre **caracteres**, no bytes: la «ñ» es un carácter aunque ocupe 2 bytes en UTF-8 (lo viste en el mundo 03).

## Bajo el capó

<BajoElCapo>

**`for` es azúcar de `loop` + iterador.** Un **iterador** (*iterator*) es algo que sabe dar «el siguiente elemento» o decir «ya no quedan». El compilador traduce `for x in algo { cuerpo }` a algo así:

```rust
let mut it = algo.into_iter();
loop {
    match it.next() {
        Some(x) => { cuerpo }
        None => break,
    }
}
```

No te preocupes por `Some`/`None` todavía (mundo 09): la idea es que **el bucle termina cuando el iterador dice que no quedan elementos**. Por eso un `for` nunca se pasa.

**La comprobación de límites.** Cuando sí usas índices (`notas[i]`), Rust comprueba en cada acceso que `i` sea menor que la longitud. Si no lo es, **entra en pánico** (*panic*): detiene el programa con un mensaje claro en lugar de leer memoria que no pertenece al array. Leer fuera de un array es un clásico **comportamiento indefinido** (UB): el programa podría leer basura, datos secretos o romperse más tarde sin explicación. Rust lo convierte en un error inmediato y visible.

**¿Y el coste?** Comprobar el límite es una comparación. Con `for x in notas` ni siquiera eso: el compilador sabe que el iterador nunca se sale y no comprueba nada.

</BajoElCapo>
