## La idea

`while condición { ... }` es como un `loop` con un `if` incorporado al principio: **antes de cada vuelta** comprueba la condición; si es verdadera, ejecuta el cuerpo y vuelve a empezar; si es falsa, sale. Si la condición ya es falsa la primera vez, el cuerpo **no se ejecuta nunca**.

Úsalo cuando sabes **la condición para seguir**, pero no cuántas vueltas harán falta: «mientras queden cifras», «mientras no llegue a 1». En `while` también puedes usar `break` y `continue`, igual que en `loop`.

Lo que **no** puedes es salir con `break valor`. ¿Por qué? Un `while` puede terminar de dos maneras: por un `break` o porque la condición se volvió falsa. En el segundo caso no hay ningún valor que entregar. Por eso un `while` siempre vale `()`, y Rust te avisa si intentas otra cosa.

## Pruébalo

<Ejecutar ej="m04/while-collatz" />

Este es el famoso problema de Collatz: si el número es par, se divide entre 2; si es impar, se multiplica por 3 y se suma 1. Nadie ha demostrado que siempre se llegue a 1, pero con 27 se llega... tras un viaje sorprendente.

1. La condición `n != 1` dice cuándo seguir.
2. Dentro, un `if` como expresión calcula el siguiente `n`.
3. `maximo` guarda el valor más alto visto. Usamos `u64` porque los números suben mucho más de lo que parece.

## Bajo el capó

<BajoElCapo>

**`while` es azúcar de `loop`.** Escribir `while c { cuerpo }` es equivalente a:

```rust
loop {
    if !c { break; }
    cuerpo
}
```

Y de hecho el compilador lo traduce así internamente (lo puedes ver en la representación intermedia, MIR, que estudiarás en el mundo 21): una comprobación, un salto de salida y un salto de vuelta.

**Por qué el compilador necesita saberlo.** Después de un `loop` con `break valor`, el compilador **sabe** que hay valor, porque solo se sale por ahí. Después de un `while`, existe un camino (la condición falsa) sin valor. Rust analiza **todos los caminos posibles** de tu programa, no solo los que crees que ocurrirán; este análisis de caminos volverá a ser clave en los mundos 06 y 07.

</BajoElCapo>
