Vas a conocer `match`, la forma de Rust de **elegir entre muchos casos**. Es una de las herramientas más poderosas del lenguaje, y hoy das el primer paso.

## La idea

`match valor { patrón => resultado, ... }` compara `valor` con cada **patrón** (*pattern*), **de arriba abajo**, y ejecuta el **brazo** (*arm*) del primero que encaje. Un patrón puede ser un valor concreto (`6`), varios unidos con `|` (`2 | 3`), un rango (`4..=5`), el comodín `_` («cualquier cosa»), o un nombre (`x`) que encaja con todo y además guarda el valor para usarlo en el brazo.

Como `if`, `match` es una **expresión**: vale lo que valga el brazo elegido, y todos los brazos deben dar el mismo tipo.

Y lo más importante: un `match` tiene que ser **exhaustivo** (*exhaustive*). Tiene que cubrir **todos** los valores que el tipo puede tener. Si te dejas uno, no compila. Parece una exigencia pesada, pero evita una clase entera de errores: el caso «que nunca iba a pasar» y que un día pasa. El compilador hace la cuenta por ti y te dice exactamente qué falta.

## Pruébalo

<Ejecutar ej="m04/match-basico" />

1. Cada valor del dado cae en el primer brazo que le encaja.
2. `_` cubre «todo lo demás». Con un `u8` hay 256 valores posibles; sin el `_`, faltarían 0 y del 7 al 255.
3. Con `char` también funciona: `'ñ'` no está en la lista de vocales, así que cae en `_`.

Y con **guardas** (*match guards*): una condición `if` añadida al patrón.

<Ejecutar ej="m04/match-guarda" />

El patrón `x` encaja con cualquier número y lo llama `x`; la guarda `if x < 0` decide si ese brazo se queda con él. El último brazo, `x => ...`, no tiene guarda, así que recoge todo lo que quede: por eso el `match` es exhaustivo aunque no haya `_`.

## Bajo el capó

<BajoElCapo>

**Cómo sabe Rust que falta algo.** El compilador conoce todos los valores de cada tipo: un `u8` va de 0 a 255; un `bool` es `true` o `false`. Con los patrones de tu `match` calcula qué valores quedan sin cubrir. Por eso el error puede decirte «`0_u8` and `7_u8..=u8::MAX` not covered» (no se cubren el 0 ni del 7 al máximo).

**Las guardas no cuentan para la exhaustividad.** Como `x if x < 0` depende de una condición que se evalúa al ejecutar, el compilador no puede usarla para demostrar que has cubierto algo. Por eso siempre hace falta un brazo final sin guarda.

**Brazos inalcanzables.** Si pones `_` primero, los brazos de debajo no se elegirán nunca. Rust lo compila, pero avisa: «warning: unreachable pattern», con la nota «no value can reach this» (ningún valor puede llegar aquí).

**Cómo se ejecuta.** Un `match` sobre números se suele compilar a una cadena de comparaciones o, si los casos son muchos y seguidos, a una **tabla de saltos**: una lista de direcciones indexada por el valor, que salta directamente al brazo correcto.

</BajoElCapo>

## Trampa típica

<Trampa titulo="El comodín demasiado pronto">

❌ El orden importa. Aquí el `_` se queda con todo, y `7` nunca se elige:

```rust
let texto = match n {
    _ => "cualquiera",
    7 => "siete",
};
```

✅ Pon los casos concretos arriba y el `_` siempre **el último**. Y no ignores el aviso «unreachable pattern»: casi siempre es un brazo mal colocado.

</Trampa>
