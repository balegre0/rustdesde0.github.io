## La idea

Los enteros no sirven para 3,75 ni para 0,000001. Para eso están los números de **coma flotante** (*floating point*): `f32` (4 bytes) y `f64` (8 bytes). Siguen una norma que usan casi todas las CPU: **IEEE 754**. Rust escribe los decimales con punto: `3.75`.

La idea es la de la notación científica, pero en base 2. En lugar de 3,75 = 3,75 × 10⁰, se escribe 3,75 = 1,111₂ × 2¹. Un `f32` guarda tres piezas:

```text
 1 bit    8 bits       23 bits
[signo][ exponente ][      mantisa      ]
```

- **Signo** (*sign*): 0 positivo, 1 negativo.
- **Exponente** (*exponent*): la potencia de 2. Se guarda sumándole 127, el **sesgo** (*bias*), para no necesitar negativos. Si se guarda 128, el exponente real es 1.
- **Mantisa** (*mantissa* o *significand*): las cifras binarias que van detrás de «1,». El 1 inicial no se guarda: siempre está ahí.

El problema: igual que 1/3 = 0,333… nunca termina en decimal, **0,1 nunca termina en binario** (0,000110011001100…). Con 23 bits hay que cortar, y lo guardado es una aproximación.

## Pruébalo

`to_bits` te da los 32 bits de un `f32` sin cambiarlos, para que puedas mirarlos. El programa separa las tres piezas:

<Ejecutar ej="m01/bits-de-un-f32" />

Salida real:

```text
     1 -> 0x3f800000 -> signo 0 | exponente 01111111 (127) | mantisa 00000000000000000000000
     2 -> 0x40000000 -> signo 0 | exponente 10000000 (128) | mantisa 00000000000000000000000
    -2 -> 0xc0000000 -> signo 1 | exponente 10000000 (128) | mantisa 00000000000000000000000
   0.5 -> 0x3f000000 -> signo 0 | exponente 01111110 (126) | mantisa 00000000000000000000000
   0.1 -> 0x3dcccccd -> signo 0 | exponente 01111011 (123) | mantisa 10011001100110011001101
0x40490fdb es 3.1415927
0.1 guardado de verdad: 0.10000000149011611938
```

Léelo así: 1 = 1,0 × 2⁽¹²⁷⁻¹²⁷⁾ = 1,0 × 2⁰. El 2 solo cambia el exponente (128 → 2¹). El −2 solo cambia el signo. El 0,5 es 2⁻¹ (126 − 127). Y el 0,1 tiene una mantisa que repite `1001` hasta que se acaban los bits: por eso lo guardado es 0,10000000149…, no 0,1.

## Bajo el capó

<BajoElCapo>

La norma reserva algunas combinaciones para **valores especiales**:

<Ejecutar ej="m01/flotantes-especiales" />

Salida real:

```text
1 / 0     = inf
+0 bits   = 0x0000000000000000
-0 bits   = 0x8000000000000000
+0 == -0  : true
0 / 0     = NaN
NaN == NaN: false
es NaN    : true
```

- **Infinito** (*infinity*): exponente todo a 1 y mantisa a 0. Sale, por ejemplo, de dividir entre 0.
- **Dos ceros**: +0 y −0 solo se diferencian en el bit de signo. Se consideran iguales.
- **NaN** (*Not a Number*, «no es un número»): exponente todo a 1 y mantisa distinta de 0. Sale de operaciones sin sentido como 0/0. Un NaN **no es igual a nada, ni a sí mismo**.
- **Subnormales** (*subnormals*): con el exponente todo a 0, el 1 inicial implícito desaparece y se pueden guardar números aún más cerca del cero, con menos precisión.

Lo de NaN tiene consecuencias en Rust: como `x == x` no siempre es cierto para un flotante, los flotantes no cumplen las reglas de una igualdad «total». Lo verás cuando aprendas los traits `PartialEq` y `Eq`.

Un `f64` funciona igual con 11 bits de exponente (sesgo 1023) y 52 de mantisa. Tiene muchos más decimales de precisión, por eso es el tipo decimal por defecto de Rust.

</BajoElCapo>

❌ Comprobar si un cálculo con decimales «da exactamente» un valor.

✅ Pregunta si está **lo bastante cerca**: si la distancia entre los dos números (su resta, sin signo, con `abs()`) es menor que una tolerancia que elijas según tu problema.

<Ejecutar ej="m01/comparar-flotantes" />

Salida real:

```text
0.1 + 0.2 = 0.30000000000000004
suma == 0.3: false
cerca de 0.3: true
```

Para dinero, donde cada céntimo cuenta, lo habitual es no usar flotantes: se guardan céntimos en un entero.
